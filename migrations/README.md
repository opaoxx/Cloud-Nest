# 数据库迁移与验证

首期版本 1 包含八张业务表。B4 的版本 2 独立新增 `upload_parts`。B5 的版本 3 新增 `change_events` 和 `sync_devices`，沿用已有的 `users.change_seq`。版本 4 增加 `file_versions`。版本 5 为 `upload_tasks` 增加替换目标、预期版本和两种结果版本。`schema_migrations` 记录迁移文件摘要、dirty 状态与执行时间。

## 使用

在项目根目录执行以下命令。目标数据库须已存在。

~~~powershell
go run ./cmd/database -database cloudnest -seed
~~~

环境变量控制连接及首次业务账号密码。

| 环境变量 | 开发默认值 |
|---|---|
| CLOUDNEST_DB_ADDRESS | 127.0.0.1:13309 |
| CLOUDNEST_DB_USER | root |
| CLOUDNEST_DB_PASSWORD | root |
| CLOUDNEST_ADMIN_PASSWORD | root |

-seed 在事务中创建或补齐业务 root 账号及其真实根目录。账号已存在时沿用原密码及配额。初次密码使用 bcrypt cost 12 保存，初始配额为 107374182400 字节。

工具在专用连接上获取数据库级命名锁并设置 UTC 会话。它先只读检查迁移表，按版本升序确认历史是内嵌清单从首项开始连续匹配的一段。跳号、未知版本、`dirty` 和摘要失配会阻止后续写入。空历史必须通过业务库为空的检查，才能创建迁移表和执行首期 SQL。服务启动检查使用同一清单，并要求清单中的版本已全部应用。SQL 文件统一 LF 换行。 [第 559 步学习记录](../docs/开发学习记录.md#第-559-步在迁移前只读核对已应用历史)

## 失败处理

MySQL DDL 会隐式提交。工具只执行历史末尾尚未应用的版本。每个版本先写 `dirty=true`，该版本的全部语句成功后才标记为 `false` 并记录完成时间。中途失败时停止后续版本，保留现场，带 `dirty` 的历史会阻止再次执行。

恢复时先检查错误、现存表和迁移记录，确认失败边界。空库初始化可以从已验证的空库基线重新开始，已有业务数据的环境必须根据备份和已执行 DDL 制定恢复步骤。人工恢复后的结构需要再次核对，再处理 dirty 记录。

已应用的迁移文件保持版本固定，后续结构变化使用新版本。空库依次应用版本 1～5。合法 v4 的库只执行版本 5，已有上传任务的四个替换字段均为 `NULL`，原业务记录以及前四版迁移记录保留。 [第 812 步学习记录](../docs/开发学习记录.md#第-812-步新增上传替换任务绑定与结果版本迁移)

后端启动时将 `schema_migrations` 与内嵌清单逐一核对，要求版本 1～5 都存在、`dirty=false` 且 SHA-256 与原 SQL 一致。版本缺失或清单之外的记录会阻止启动。此检查不自动迁移、不清除 dirty，也不验证实际表结构的所有差异。 [第 557 步学习记录](../docs/开发学习记录.md#第-557-步按内嵌迁移清单校验启动版本)

## 隔离集成验证

测试使用专用测试库，库名必须以 cloudnest_migrate_verify_ 开头。先由管理员创建一个全新的测试库，然后执行以下流程。

~~~powershell
go run ./cmd/database -database cloudnest_migrate_verify_local -seed
$env:CLOUDNEST_SCHEMA_TEST_DB = 'cloudnest_migrate_verify_local'
go test -count=1 -v ./cmd/database
~~~

验收完成后，管理员可以清理本次专用测试库。普通 go test ./... 在未指定测试库时会跳过数据库集成项。

已完成的验证覆盖如下内容。

- 同用户复合外键、重复根目录、归一化名称冲突及同名回收记录。
- READY 对象校验信息、同账号去重唯一键、已引用对象删除拦截。
- 上传终态、预占释放、重复完成的 SQL 幂等结算。
- 并发配额预占、回收占用、清理事务回滚、偏好与文件版本隔离。
- 迁移重复执行、dirty 保护、摘要不一致保护、重复初始化保留密码。
- 从开发库导出结构和初始数据，恢复到独立库，九张表完整且逐行数据导出一致。

父目录必须为目录、循环与深度检测、祖先可见性、规范化名称生成、对象实际哈希校验、GC 与任务恢复仍由后续业务层执行。这里的集成验证针对数据库约束及约定的 SQL 事务模式。

业务表定义见 [数据库设计方案书](../docs/数据库设计方案书.md)。
