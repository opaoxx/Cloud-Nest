## 1. 当前基线与交付范围

| 已有基础 | 设计衔接 |
|---|---|
| Go 1.27.2、Gin v1.12.0，当前入口提供 /ping | 延续单体服务，增加配置、依赖装配与业务路由 |
| MySQL 八张业务表和迁移记录 | 通过 Repository 访问，启动时校验迁移版本与摘要 |
| root 业务账号、100 GiB 配额、真实根目录 | 登录后返回真实用户与 root_entry_id |
| 本地 MinIO 私有 cloudnest 桶 | 由服务端存储适配层管理内容和签名 |
| React Web Demo | 经 API 适配器接入真实数据，保留独立体验模式 |
| 数据库集成验证 | 在其基础上增加 Service、HTTP 与故障恢复验收 |

后端默认监听 127.0.0.1:18081。MySQL 使用 127.0.0.1:13309，MinIO API 使用 127.0.0.1:19000。前端开发端口为 5173，8080–8090 和 18080 继续按项目端口约定保留。

首期覆盖登录、会话管理、文件目录、收藏、最近访问、小文件传输、配额、回收站及必要的恢复清理。Redis 业务接入、Multipart、历史版本与双向同步分别安排到后续阶段。

## 2. 架构与包结构

### 2.1 运行结构

~~~mermaid
flowchart LR
    Web[React Web] --> API[Gin HTTP]
    Native[后续桌面与移动端] --> API
    API --> Service[业务 Service]
    Service --> Repository[Repository 与事务]
    Repository --> MySQL[(MySQL)]
    Service --> Storage[对象存储适配]
    Storage --> MinIO[(MinIO)]
    Worker[后台恢复与清理任务] --> Service
    Web -->|短期授权下载| MinIO
~~~

首期 API 和 worker 共用一个 Go 进程。业务状态、租约与恢复条件落在 MySQL。服务重启后通过持久状态继续处理。

### 2.3 数据访问和事务约定

沿用总方案的 GORM 选择，底层驱动复用已有 go-sql-driver/mysql。第 009 小步已固定 S3 SDK 为 minio-go v7.4.1，第 019 小步固定 GORM v1.31.2、gorm.io/driver/mysql v1.6.0，底层 mysql 驱动仍为 v1.9.2，第 033 小步固定 JWT 库 github.com/golang-jwt/jwt/v5 v5.3.1，版本写入 go.mod/go.sum。

第 004 小步先在 repository.OpenMySQL 中复用当前驱动建立 *sql.DB 连接池，后续 GORM 装配复用此池。连接使用 utf8mb4、ParseTime=true 和 UTC 会话，不启用迁移专用 MultiStatements。启动 PingContext 最多 5 秒，也遵守调用方更短期限；失败关闭池并停止启动。连接最大寿命暂定 3 分钟，池数量沿用本方案 10/5。

第 019 小步已提供 repository.NewStore(existingPool)，复用已有 *sql.DB，不接管关闭，不执行版本探测、自动 Ping 或 AutoMigrate，并关闭原始 SQL 日志。FindLoginAccountByUsername 通过最多 5 秒、服从调用方期限的 WithContext 查询，仅选择 id/password_hash/status，参数绑定用户名且限制一条结果；models.LoginAccount 为只读三列投影，映射到 domain.LoginAccount 后返回。未命中是 domain.ErrAccountNotFound，底层失败保留错误链并返回 nil 账号，禁用状态仍返回供业务层判断。摘要不参与 JSON 序列化、不返回前端、不记录日志。当前通过测试调用查询，尚未在 main 中装配无消费者的 Store 或注册登录端点。

第 025 小步已提供 Store.FindLoginDeviceByInstallation(ctx, userID, installationID)，在非零且已验证的用户范围内绑定 user_id 与 installation_id 两个条件，最多 5 秒只读查询 user_devices 的 id/user_id/installation_id/name/platform/revoked_at 六列。models.LoginDevice 为只读投影，映射到 domain.LoginDevice；撤销时间使用 *time.Time，未撤销保留 nil，已撤销记录也返回，由业务层决定后续处理。未命中为 domain.ErrDeviceNotFound，其他故障保留错误链且不返回部分设备；不创建、恢复或更新设备，也不注册 HTTP 路由。

第 026 小步已提供登录专用 Store.WithLoginUserTransaction(ctx, userID, action)：最多 5 秒，按 users 主键 FOR UPDATE 锁定读取 id/status 并复查 ACTIVE，随后把事务上下文和绑定同一 sql.Tx 的 Store 交给回调。回调只使用这两个参数；成功后提交，错误/取消/panic 时尝试回滚，正常错误路径保留回滚故障原因，原 panic 不被替换。禁止嵌套，不自动重试；提交故障不宣称结果确定。此入口不校验尚未建立的登录会话，已认证请求所需的通用 actor/session 事务入口仍按下述约定后续实现。

第 027 小步已提供 Store.CreateLoginDevice(ctx, installationID, name, platform)：仅允许上述事务 Store，user_id 来自复查成功后设置的私有 loginUserID；输入字段先经 DTO 校验。本方法用独立 models.NewLoginDevice 显式插入 user_id/installation_id/name/platform，回填自增 ID，其他列沿用数据库默认值；不使用 Save/Upsert，不覆盖或恢复已有设备。1062 唯一键冲突返回固定 ErrDeviceAlreadyExists，其他错误保留原因，失败无部分对象；上下文最多 5 秒且服从事务期限，结果必须影响一行并取得非零 ID。成功返回 domain.LoginDevice 仍须等待外层事务提交确认。当前仅测试装配，设备复用和会话编排在后续小步实现。

第 028 小步已提供 Store.EnsureLoginDevice(ctx, installationID, name, platform)，供凭证验证成功后的用户事务调用。按锁定用户查询，缺失时沿用 CreateLoginDevice，已有设备保留 ID、名称和平台。用户于 2026-11-11 确认重新登录可恢复撤销设备，该分支按 user_id/id 限定条件清空 revoked_at 并用数据库 UTC 时间更新 updated_at，要求影响一行。旧 auth_sessions 保留各自撤销状态。整个方法最多 5 秒并服从外层期限，查询/创建/恢复故障返回外层事务，异常归属或结果为 ErrInvalidDeviceData。外层提交成功后设备准备完成。

第 030 小步已提供 Store.CreateLoginSession(ctx, deviceID, tokenHash, expiresAt)。用户归属取自事务，设备按 user_id/id FOR UPDATE 锁定复查，缺失/撤销/异常归属分别返回 ErrDeviceNotFound、ErrDeviceRevoked、ErrInvalidDeviceData。到期时间转为 UTC 并截断到微秒，要求在数据库日期范围内且插入前仍有效。NewLoginSession 显式插入 user_id/device_id/refresh_token_hash/expires_at，代次 1 和其余初始字段沿用表默认值。摘要参数为固定 32 字节数组，模型内部转字节切片。1062 转为固定 ErrRefreshTokenConflict，异常结果为 ErrInvalidSessionData，其他故障保留错误链。返回 LoginSession 的 ID/UserID/DeviceID/ExpiresAt，外层提交后确认生效，设备准备与会话写入共用同一事务。

第 035 小步提供 Store.FindSessionAuthorization(ctx, userID, sessionID)，通过普通一致性读取关联 auth_sessions、users 与 user_devices。WHERE 同时绑定会话的 user_id/id，设备按会话 user_id/device_id 连接，显式读取七列。只读投影转换为 domain.SessionAuthorization，包含用户/会话/设备 ID、用户状态、会话到期时间及两类可空撤销时间，禁用/撤销/过期事实由后续服务层判断。查询最多 5 秒并服从调用方期限，取消、未命中、数据库故障及标识异常分别处理，失败无部分对象。该入口供普通请求授权读取，关键写事务继续按用户锁和当前读复核状态。

第 042 小步提供 Store.FindUserProfile(ctx, userID)，按已验证用户 ID 关联 users 与 file_entries，显式读取 ID、登录名、展示名、账号状态、真实根目录 ID 和配额/已用/预占字节八列。根目录通过 root_owner_id 唯一键及 user_id 归属关联，限定 parent_id 为空、DIR、ACTIVE。LEFT JOIN 保留缺少根目录的用户记录，账号不存在为 ErrAccountNotFound，根目录缺失/异常或配额不一致为 ErrInvalidAccountData。配额检查先比较已用量，再用减法比较预占，覆盖完整 uint64 范围。查询最多 5 秒，服从调用方期限与取消，数据库故障保留原因，状态由后续服务层判断。普通一致性读取返回本次资料与配额快照，供登录响应及 /me 后续装配。

第 043 小步提供 UserProfileService.Get(ctx, userID)，注入 Store.FindUserProfile，输入 ID 来自凭证验证或 Actor。查询前后检查取消，未找到沿用 ErrAccountNotFound，其他查询错误保留原因。结果须非空、用户归属一致并包含真实根目录 ID，ACTIVE 返回资料副本，DISABLED 返回 ErrAccountDisabled，未知状态返回 ErrInvalidAccountData。根目录及配额检查继续由 Repository 完成。真实 MySQL 独占库验证资料读回、禁用与重新启用后的状态复查、未找到、根目录异常和数据库故障，供登录资料与当前用户接口后续装配。

第 051 小步提供 Store.FindRefreshSession(ctx, tokenHash)，以固定 32 字节数组接收刷新原文的 SHA256。通过摘要唯一键参数绑定定位 auth_sessions，再按用户及设备归属关联 users/user_devices，读取七列授权状态与 token_generation。RefreshSession 嵌入已有 SessionAuthorization，保留账号状态、会话期限和可空撤销时间，代次及三个标识须非零。未找到沿用 ErrSessionNotFound，其余数据库故障保留原因。查询最多 5 秒并服从调用方期限及取消，采用普通一致性快照供初次定位，轮换更新继续在用户事务内复查当前摘要、代次和授权状态。

第 085 小步提供 UserDeviceService.List(ctx, actor, beforeDeviceID, pageSize)，构造时绑定 ListUserDevices。服务检查完整 Actor、页大小与上下文，使用同一上下文和 Actor.UserID 查询，取消优先于查询错误分类。结果须存在，页长符合上限及 HasMore，设备归属与非零 ID 正确，记录严格倒序且小于游标。UserDeviceListItem 嵌入设备事实，按 ID 与 Actor.DeviceID 相同标记 Current，UserDeviceList 保留 HasMore。返回列表独立分配，两项可空时间逐项复制，保留历史事实并在返回前复查取消。异常结果沿用 ErrInvalidDeviceData，查询故障保留原因。单元及真实 MySQL/JWT 联测验证同设备多会话标记一致、不同设备及后续页、账号隔离、历史时间、完整 uint64、取消与副本独立性，响应 DTO 与 HTTP 接入按后续步骤实施。

第 086 小步提供 dto.NewUserDeviceListData(result)，接收已完成归属、分页及 Current 检查的 UserDeviceList。UserDeviceSummary 嵌入已有 LoginDeviceSummary 并平铺字符串 ID、名称和平台，增加创建时间、两项可空时间及 current，共七个公开字段。UserDeviceListData 使用 items/has_more，UserDeviceListResponse 使用 data/request_id。空列表初始化，false 及 null 明确交付。时间复用提取出的 listResponseTime，复制为 UTC 微秒值并检查 UTC 年份 1000～9999，设备异常映射 ErrInvalidDeviceData，会话列表转换继续映射 ErrInvalidSessionData。空结果、超过 100 条、空页 HasMore 冲突、零标识和无效时间返回空 DTO。OpenAPI 提供三个设备列表共享结构，单元测试覆盖 JSON 字段、完整 uint64、时间边界、副本独立性与真实 Service 配合内存查询结果的衔接。查询参数及 HTTP 接入按后续步骤实施。

第 087 小步提供 dto.ParseUserDeviceListQuery(rawQuery)，将完整查询字符串转换为 BeforeDeviceID/PageSize。省略或显式 before_id=0 为首页，范围覆盖完整 uint64，limit 默认 50 且范围为 1～100。将会话列表原有解析规则提取为私有 parseListQuery，两类公开 DTO 复用整体 URL 解析、重复值检查及标准十进制转换，分别提供设备或会话边界提示。额外字段采用忽略策略，整体解析错误优先定位 query，其后依次定位 before_id、limit，错误返回空 DTO。OpenAPI 增加 UserDeviceBeforeID/UserDeviceLimit 共享参数。单元、HTTP 测试入口和设备 Service 配合内存查询的衔接覆盖默认值、边界、编码、字段错误与身份来源，现有会话查询回归通过。

第 088 小步提供 handler.UserDevices(listDevices)，路由先挂载认证中间件，处理函数从上下文读取 Actor，解析完整 RawQuery 并调用设备服务。服务调用前后及编码响应后复查取消，服务错误复用 AuthorizationFailure，参数错误复用 InvalidArgument。核对结果归属并使用 NewUserDeviceListData 转换，预先编码 UserDeviceListResponse，交付 HTTP 200、no-store、Pragma no-cache 及请求 ID，清理待提交正文头并结束处理。已提交响应直接结束，空结果、错误归属和非法 DTO 进入统一 500。OpenAPI 增加 UserDevicesListed 共享响应。内存 HTTP 场景与独占 MySQL/JWT/HTTP 联测验证分页、历史事实、同设备多会话、身份来源、取消及禁用/撤销边界，正式路由与启动接入按下一小步实施。

第 089 小步将 GET /api/v1/devices 接入正式路由和启动装配。RegisterUserDevicesRoute 先构造 RequireAuthorization，再绑定 UserDevices。main.run 复用已有连接池和 Store 构造 UserDeviceService，使用共享 AuthorizationService 注册接口。OpenAPI 正式操作 listUserDevices 使用 BearerAuth、UserDeviceBeforeID/UserDeviceLimit 和 UserDevicesListed。正式路由测试覆盖认证、默认/后续/最大边界分页、参数拒绝、预检、公共检查、方法与尾斜杠及依赖缺失。真实 run 测试使用正式迁移独占库、临时签名配置和空闲端口，核对每条设备的数据库归属、展示字段和时间事实，验证两轮启动中的分页、同设备多会话、重启一致性及禁用/撤销/恢复/退出状态。

第 090 小步提供 RenameDeviceRequest{Name}，请求正文使用 name，Validate 复用从登录校验中提取的 validDeviceName。名称须为有效 UTF-8、1～100 个 Unicode 码点、非全空白且无控制字符，保留原始空白、大小写及 Unicode 文本。修改名称失败定位 name，登录失败继续定位 device_name，均使用固定设备名称提示。OpenAPI 提供 RenameDeviceRequest 共享结构，name 引用登录设备名称的同一规则。单元覆盖名称边界、控制字符、JSON 往返及登录规则一致性；PATCH 测试入口组合 ReadJSON、Validate 与 InvalidArgument，覆盖未知字段、类型错误、格式错误、正文大小和编码规则。路径参数、设备归属和名称更新按后续小步接入。

第 091 小步提供 UserDevicePath{DeviceID} 与 ParseUserDevicePath，接收路由已解码的 id，转换为范围 1～18446744073709551615 的标准十进制 uint64。零、前导零、符号、空白、小数及溢出返回空 DTO 和固定 id 字段错误。原会话路径数字规则提取为私有 parsePathID，两类路径分别使用设备/会话提示，重复调用的结果及错误对象独立。OpenAPI 提供 UserDeviceID 共享路径参数。单元与认证 PATCH 测试入口覆盖完整范围、解码及路径边界，串联 RenameDeviceRequest 验证认证、路径、正文和名称校验顺序，后续业务流程负责目标归属及名称更新。

用户请求的 actor 由认证中间件构造。worker 使用内部任务身份，用户归属来自数据库任务记录，并校验任务阶段和租约。后台任务在客户端退出后可继续恢复，账号被禁用时终止未完成发布并结算预占，清理工作继续遵循引用与保留期规则。

第 036 小步提供 AuthorizationService.Authorize(ctx, tokenText)，注入令牌 Verify 与授权信息查询。令牌失败结束流程，查询使用已验证的 user_id/session_id，未找到与数据库故障分别处理。结果须与令牌归属一致、设备 ID 非零且包含有效到期时间。检查顺序为账号状态、会话/设备撤销、令牌/会话截止时间，未知账号状态按内部数据异常处理。查询后及成功返回前检查取消，成功返回 domain.Actor 的 UserID/SessionID/DeviceID，供后续认证中间件保存到请求上下文。当前服务与真实签发/校验组件配合内存状态数据验证，关键写入继续按事务内状态复核约定实施。

第 038 小步提供 requestcontext.WithActor(parent, actor) 与 Actor(ctx)。调用方先完成授权，WithActor 要求三个身份 ID 非零，使用私有类型键按值附加到子上下文，保留父上下文的请求 ID、其他值、取消与期限。nil 父上下文或缺少身份标识作为调用错误触发 panic。Actor 返回身份副本与存在标记，nil 上下文、缺失或类型错误返回零值和 false。测试入口在授权成功后用 Request.WithContext 传递子上下文，下游处理函数据此读取身份。关键写入继续按事务内当前状态复核。

第 039 小步提供 middleware.RequireAuthorization(authorize, reject)，受保护路由显式挂载，注入 AuthorizationService.Authorize 与 handler.AuthorizationFailure。请求先检查取消并提取凭证，调用授权服务后复查取消，成功结果须包含三个非零身份 ID，随后按值附加 Actor 并继续下游。失败回调结束后中间件执行 Abort。固定响应映射为凭证缺失/格式或 JWT 无效 → AUTH_REQUIRED 401，令牌过期 → TOKEN_EXPIRED 401，会话未找到/到期/撤销或设备撤销 → SESSION_REVOKED 401，账号禁用 → ACCOUNT_DISABLED 403。未分类故障、异常身份及取消/超时沿用 INTERNAL_ERROR 500。401 附带 Bearer 认证提示，错误包含请求 ID、details=null 与 no-store。当前通过测试专用路由、真实 JWT 与内存状态提供方验证，后续业务操作按需装配。

文件业务锁顺序沿用数据库方案，按 users → file_entries → stored_objects → upload_tasks → user_entry_preferences → idempotency_records 执行，同表按主键升序。认证业务采用 users → user_devices → auth_sessions。写事务中的会话有效性通过当前读复核，并与撤销流程遵循相同用户锁。

事务回调内全部使用绑定的 tx 句柄。数据库事务与对象网络调用之间用持久状态连接。[GORM 事务文档](https://gorm.io/docs/transactions.html)

持久化模型逐字段映射已存在的表名、类型、主键和索引语义。root_owner_id、active_name_key、dedup_hash 标记为只读生成列，列清单显式排除这些字段的写入。结构升级由 cmd/database 与版本迁移完成。

第 031 小步提供 config.LoadJWTConfig(localSecret)，由调用方传入本地密钥文本，环境变量明确设置时优先覆盖。密钥严格解码标准无填充 Base64URL 并检查规范编码与至少 32 字节长度，SigningKey 保存解码后的字节且从 JSON 排除。issuer/audience 使用上述默认值，要求有效 UTF-8、非空、无首尾空白及控制字符，并保留大小写。两个 TTL 通过 time.ParseDuration 读取且要求为正整数秒，显式空值按无效配置处理。任一失败返回零值配置和固定字段错误。当前通过配置测试入口验证，后续接入本地密钥初始化与保存，再装配到签发流程。

第 032 小步提供 config.LoadOrCreateJWTConfig(secretPath)。明确设置环境密钥时直接沿用 LoadJWTConfig，否则读取既有密钥文件，内容有效时复用。仅文件不存在时生成 32 字节安全随机数，编码并校验配置后准备目录，写完同目录临时文件、Sync/Close，再以硬链接发布正式文件名。目标已经存在时重新读取最终文件，让并发初始化者复用同一密钥。已有坏文件返回错误并保留。新目录和文件的创建模式分别为 0700/0600，Windows 访问权限由所在目录 ACL 决定，文件系统需支持硬链接。路径由启动装配方指定，可位于 os.UserConfigDir() 下的 CloudNest/jwt-secret。本轮通过真实文件与独立进程测试验证，后续启动及签发组件使用该入口。

第 003 小步已实现 MySQL 的环境变量配置入口：CLOUDNEST_DB_ADDRESS、CLOUDNEST_DB_NAME、CLOUDNEST_DB_USER、CLOUDNEST_DB_PASSWORD。目前尚未加载本地配置文件；变量未设置时使用表中开发默认值，显式空地址、空库名及空白用户名报错，密码原样保留（包括空字符串）。数据库地址要求明确主机和 1～65535 的数字端口。第 004 小步已接通连接和认证检查；第 005 小步已接入迁移记录检查；第 007 小步已实现退出信号处理；第 010 小步已实现请求时依赖就绪检查。

第 015 小步已实现 config.LoadAllowedOrigins：读取逗号分隔的 HTTP(S) 来源，规范化大小写、常规 IPv6 及默认端口，按首次出现顺序去重；显式空值、空条目、通配符、凭证、业务路径、查询和片段会报错，不回显原始输入。当前支持 ASCII 域名、标准 IPv4 和带方括号且无区域/IPv4 映射的 IPv6，国际化域名采用 punycode。main 在连接依赖前读取并记录配置。第 016 步将列表显式传入路由，按单个规范来源严格匹配；无 Origin 继续，未知/空/null/重复来源或非法预检返回统一 CORS_FORBIDDEN 403。允许的普通响应包含明确 Allow-Origin、Allow-Credentials: true，并暴露 X-Request-ID；合法预检返回无正文 204、no-store，不执行接口。所有响应按 Origin 区分缓存，OPTIONS 再按预检方法和头区分；关闭尾斜杠自动重定向，保证这类请求也先检查来源。

第 008 小步已实现 config.LoadStorageConfig，读取 provider、两个 S3 地址、bucket、access key 与 secret key。当前仅支持 local_minio；地址解析为 *url.URL，支持 HTTP/HTTPS、IPv4、带方括号的 IPv6，显式端口要求 1～65535，不允许嵌入凭证、非根路径、查询参数或片段。桶名遵循 MinIO 严格校验的基础规则，凭证非空且保持原值；错误不回显原始输入。第 009 小步已接入存储 SDK 与已有桶访问检查。后续签名必须使用目标访问地址生成，不在签名后替换 URL 主机。

storage.NewClient 使用内部地址、静态 V4 凭证和 path-style 访问创建 minio-go v7.4.1 客户端，调用 CheckBucket 在最多 5 秒内只读检查已有桶，服从调用方取消或更短期限。每个客户端独占 Transport，关闭 SDK 自动重试，保持 HTTPS 证书校验；缺桶或访问失败停止启动并记录 stage=storage，不自动创建桶。HTTP 退出后先释放存储空闲连接，再关闭 MySQL 池。CheckBucket 供后续就绪检查复用，公开地址和对象操作随对应业务功能验证。

repository.CheckSchema 在最多 5 秒内只读核对 schema_migrations，目前仅接受版本 1 的单条记录，要求 dirty=false，checksum 与程序内嵌初始 SQL 的 SHA256 一致。缺表、缺记录、未知版本、dirty、摘要不一致或读取错误均停止启动并记录 stage=schema。本检查不自动执行迁移，不逐列验证实际表结构；迁移期间仍按维护流程操作。

启动顺序为初始化固定格式的启动日志、读取并校验配置、连接数据库、核对 schema_migrations、初始化存储客户端、启动 worker、启动 HTTP。日志先于配置创建，使配置错误也能统一输出。迁移版本不兼容或 dirty=true 时停止启动。

/health/live 表示进程可响应，第 006 小步已实现 GET、无需登录、HTTP 200 和 {"status":"ok"}，请求处理不访问数据库或存储。第 010 小步已实现 GET /health/ready：无需登录，两项依赖检查共享最多 5 秒，全部通过返回 200 与 {"status":"ready"}，任一失败、超时或取消返回 503 与 {"status":"not_ready"}；设置 Cache-Control: no-store，不回显底层错误或凭证。HealthService 依次调用 MySQL PingContext 和存储 CheckBucket，失败立即返回，故障恢复后下次请求重新检查。/ping 保留现有响应，便于开发工具继续使用。路由由 http.NewRouter 创建，具体请求处理位于 http/handler，启动入口负责依赖装配与监听。

数据库池初始 MaxOpenConns=10、MaxIdleConns=5，SQL 请求超时初始为 5 秒。JSON 请求体限制 1 MiB。第 017 步已提供 binding.ReadJSON(ctx, &requestDTO) bool，由需要 JSON 的 Handler 显式调用；现有三个系统 GET 不读取正文。只接收未压缩的 UTF-8 application/json，按实际字节受限读取，再解析单个对象并拒绝未知字段、类型错误或多段 JSON。输入错误返回 INVALID_ARGUMENT 400、REQUEST_BODY_TOO_LARGE 413 或 UNSUPPORTED_MEDIA_TYPE 415，沿用统一错误结构和请求 ID，不回显原始输入。必填和业务规则由后续 DTO 校验处理；失败时 Handler 必须立即 return，禁止使用部分解析的数据。HTTP ReadHeaderTimeout 初始为 5 秒，小文件传输使用独立的请求总时限，初始为 5 分钟。退出时先停止领取任务，等待在途请求和 worker 最多 30 秒，再关闭资源，剩余租约由重启恢复处理。

第 007 小步已使用标准库 http.Server 管理 Gin 路由，ReadHeaderTimeout=5 秒。main 将中断信号转换为上下文取消，传递给启动检查及 http.Serve；HTTP 使用独立的 30 秒 Shutdown 期限等待在途请求，失败时 Close 强制关闭并返回错误。Serve 返回后关闭 MySQL 池。正常中断退出码为 0，真实配置、依赖或 HTTP 运行/关闭错误为 1。worker 与升级连接的退出处理随其引入补充。

## 4. 统一 HTTP 契约

### 4.1 数据类型

- 业务路由统一位于 /api/v1。
- 用户、设备、文件、任务 ID 和 revision 使用十进制字符串。
- 字节数使用 JSON number，服务端限制在 JavaScript 安全整数范围内，当前配额和文件上限满足该范围。
- 时间输出 UTC RFC 3339，最多保留数据库的六位小数。
- 可空值显式返回 null。列表没有下一页时 next_cursor 返回 null。
- 前端展示名、扩展名、分类由 DTO 提供。Storage 的对象键及凭证由服务端持有。
- 请求带 X-Request-ID 时仅接受单个标准 36 字符 UUID v4（RFC 4122 variant），合法值规范成小写，否则生成新 UUID v4，不因标识无效拒绝原请求。第 011 小步已将最终 ID 写入标准请求上下文及请求/响应头，多个同名头或合并值同样替换；第 012 小步已让统一请求日志读取同一 ID，后续业务响应沿用该 request_id。

第 044 小步提供 dto.NewUserProfileData(profile)，将服务返回的资料映射为可复用的响应数据。采用 user 子对象保存 id、username、display_name，外层包含 root_entry_id、quota_bytes、used_bytes、reserved_bytes。用户与根目录 ID 采用完整 uint64 十进制字符串，三项字节数分别限制在 0～9007199254740991，零值明确输出。nil 资料或零 ID 返回 ErrInvalidAccountData，数字越界返回固定内部转换错误与空结果。账号状态、根目录归属及配额一致性继续由服务与 Repository 检查。UserSummary/UserProfileData 已写入 OpenAPI 共享组件，后续具体响应提供 data 与 request_id 外层。当前通过单元测试及使用测试认证回调、内存资料的真实 TCP 入口验证。

第 045 小步提供 handler.CurrentUser(getProfile)，绑定 UserProfileService.Get，挂载在认证中间件之后。用户 ID 取自 Actor，查询前后检查取消，成功资料须与 Actor 归属一致，经 DTO 转换后返回 UserProfileResponse 的 data/request_id，状态为 200，设置 no-store。账号未找到映射为 AUTH_REQUIRED 401，禁用沿用 ACCOUNT_DISABLED 403。缺少 Actor 按装配异常处理，资料异常、转换失败及取消/超时沿用 INTERNAL_ERROR 500。OpenAPI 已记录共享成功响应 CurrentUserProfile，当前通过测试路由及真实 JWT 配合内存状态的 TCP GET/HEAD 验证，实际业务路由由后续启动装配接入。

第 046 小步在 cmd/server.run 中调用 LoadServerJWTConfig，环境密钥优先，否则读取或初始化用户配置目录下的 CloudNest/jwt-secret。沿用已有文件发布、校验与复用规则，启动日志记录 issuer/audience。数据库和存储检查完成后，复用现有池构造 Store、AccessTokenVerifier、AuthorizationService 与 UserProfileService。RegisterCurrentUserRoute 在公共中间件之后为 GET /api/v1/me 挂载认证与 CurrentUser。系统检查入口继续使用各自公开契约，优雅退出沿用既有生命周期。真实启动集成测试使用正式迁移独占库、临时配置目录与已有 MinIO，验证资料返回、重启复用原 JWT、禁用/撤销及资源清理。

第 047 小步提供 dto.NewLoginData(result, profile, clientType, now)，复用 UserProfileData，增加 access_token、expires_in、device、session 及原生模式的 refresh_token。构造时核对用户、设备、会话归属，检查凭证存在、设备撤销及会话/访问有效期。expires_in 取本次响应计算时刻起实际剩余完整秒数，向下取整，未来不足一秒时为 0。所有 ID 使用十进制字符串，session.expires_at 规范化为 UTC 微秒精度。Web JSON 省略刷新原文，原生 JSON 携带刷新原文，Cookie 由后续 HTTP 交付层按既定模式处理。LoginResponse 使用 data/request_id，OpenAPI 记录共享结构，登录操作随后续步骤接入。

第 057 小步提供 dto.NewRefreshData(result, clientType, now)，接收第 056 步 RefreshTokenResult。核对非零用户/设备/会话 ID、至少为 2 的代次、准确客户端类型、两类原文存在及有效计算时间，再按 UTC 微秒会话截止时间检查数据库日期范围、访问期限上界和两类有效期。到期错误沿用 ErrSessionExpired/ErrAccessTokenExpired，异常资料为 ErrInvalidSessionData。成功数据使用 access_token 和 expires_in，原生模式增加 refresh_token，RefreshResponse 使用 data/request_id 外层。expires_in 沿用登录响应的完整剩余秒数规则，向下取整，未来不足一秒时为 0。OpenAPI 新增共享 RefreshData/RefreshResponse，凭证和秒数字段引用既有属性契约，Cookie 由后续交付层处理。

业务接口成功响应使用 data 与 request_id，失败响应使用 error 与 request_id。HTTP 状态码与业务错误同时表达结果。系统探测接口 /ping、/health/live 与 /health/ready 直接返回各自约定的简单 JSON，具体见 api/openapi.yaml。

第 013 小步已实现 NoRoute 的统一 404：error.code=ROUTE_NOT_FOUND、message=未找到匹配的接口、details=null，request_id 与上下文、响应头及日志一致；Content-Type 为 application/json，Cache-Control 为 no-store。ErrorResponse/ErrorDetail 定义在 http/dto，未匹配处理位于 http/handler/not_found.go，不访问依赖或回显请求内容。普通未注册方法沿用 404；第 016 步关闭尾斜杠自动重定向，并对来源与预检优先执行 CORS 策略。HEAD 不返回正文；其他状态错误逐小步接入。共享契约位于 components.responses.RouteNotFound，不添加虚构的通配 API。

第 014 小步已实现普通异常恢复的统一 500：响应未提交时，返回 INTERNAL_ERROR、固定提示、details=null 和当前 request_id，并清理冲突的待发送长度/编码头，设置 JSON 与 no-store。响应已提交时仅停止处理，保留实际状态、头和正文。Recovery 禁止原始转储，对交给回调的普通异常只设置 recovered_panic=true；完成日志使用 ERROR 并保留实际 status。共享契约为 components.responses.InternalError，三个系统 GET 操作均引用此 500；网络断连等特殊情况沿用 Gin 逻辑，没有增加生产异常测试接口。

### 4.2 认证与幂等头

普通业务请求使用 Authorization: Bearer access_token。创建目录、重命名、移动、回收、恢复及创建上传等业务写请求要求 Idempotency-Key，建议采用 UUID。

第 037 小步提供 security.BearerToken(request)，要求恰好一个 Authorization 头。方案名大小写兼容，方案与凭证间允许一个或多个 ASCII 空格，头值两端接受空格和水平制表符。凭证主体允许 ASCII 字母、数字和 -._~+/，可附连续末尾等号，提取成功保留原文，后续交由 AuthorizationService 执行 JWT 与数据库状态校验。缺少、重复或格式异常统一返回 ErrInvalidAuthorizationHeader 与空文本。凭证从该头读取，错误使用固定消息。真实 TCP 测试入口已串联解析器、真实令牌组件与内存会话状态提供方，生产认证中间件随后接入。

完成与取消上传依赖 task_id 和持久状态实现幂等。收藏使用 PUT 设置明确布尔状态。访问时间记录采用可合并更新。

幂等键绑定用户、版本化操作、资源 ID 与规范化请求摘要。同键同请求返回已记录结果，同键不同请求返回 409。结果中保存稳定 ID，临时签名 URL 在重新鉴权后签发。记录保留至少 7 天，客户端跨保留窗口重试时先查询已有资源。

### 4.3 错误与前端行为

| HTTP | 业务码 | 前端处理 |

## 6. 登录与会话流程

### 6.1 登录

1. 对 JSON、用户名、密码长度和安装 UUID 做格式校验。
2. 使用 bcrypt 验证已有业务账号，失败统一返回认证失败信息。
3. 检查用户状态，按 user_id 与 installation_id 找到或创建设备。
4. 在用户事务中创建 auth_sessions，随机生成 Refresh Token 并只保存 SHA256。
5. 签发 15 分钟 Access Token，返回用户、真实根目录与当前设备。
6. 节流更新设备及会话 last_seen_at，避免每次请求都写入时间。

第 029 小步已提供 service.GenerateRefreshToken()，使用 crypto/rand.Read 生成 32 字节随机数，以无填充 Base64URL 编码为 43 字符原文。SHA256 针对该原文文本计算，返回固定 32 字节数组供 auth_sessions.refresh_token_hash 入库，后续刷新按同一文本规则重新计算摘要。原文用于提交成功后的客户端交付，两项均作为敏感数据处理。函数沿用 Go 1.27 随机源读取失败时标准库终止进程的行为。未来登录服务在用户事务前生成令牌，随后在事务内写入摘要与会话。

第 040 小步提供 LoginSessionService.Create(ctx, account, installationID, deviceName, platform)。构造时共用 JWTConfig.Validate，仅保存 RefreshTokenTTL，并绑定用户事务方法、时钟与刷新凭证生成方法。输入账号须已通过凭证校验，设备字段须已通过 DTO 校验。服务先生成刷新原文与摘要，按 UTC 微秒精度计算会话截止时间，再由 WithLoginUserTransaction 复查账号并依次执行 EnsureLoginDevice、CreateLoginSession。LoginSessionTransaction 接口仅列出这两个事务操作，装配回调把真实 txContext/txStore 传入。检查设备及会话归属、撤销状态与返回期限，暂存结果副本，提交成功后返回 LoginSessionResult 的 Device、Session 与 RefreshToken。刷新原文带 json:"-"，HTTP 后续通过明确 DTO/Cookie 交付。事务错误或提交故障返回 nil 并保留错误链，提交故障只尝试一次。事务已经确认提交后，服务返回已提交结果，请求层继续处理后续取消与响应交付。真实 MySQL 独占库已验证设备复用/恢复、旧会话保留撤销、摘要冲突时回滚新建或恢复设备，以及同安装并发登录。

第 041 小步提供 LoginTokenService.Create(ctx, account, installationID, deviceName, platform)，注入 LoginSessionService.Create 与 AccessTokenSigner.Issue。服务取得已提交会话并检查完整归属后，按值交给签发器，成功返回 LoginTokenResult 的 Device、Session、AccessToken、RefreshToken。两类原文均沿用 json:"-"，HTTP 后续显式交付。依赖失败先保留原因，依赖成功后检查取消，签发结果须包含令牌与有效截止时间，访问期限受会话期限约束。错误返回空结果，已提交会话保留其提交状态。真实 MySQL 独占库已串联会话创建、JWT 签发与校验、刷新摘要读回以及数据库授权服务，提交后签发故障和取消边界均已核对。

第 020 小步已提供 service.VerifyPassword(passwordHash, rawPassword) (bool, error)：先检查本项目支持的标准 60 字符 $2a$/$2b$/$2y$ 摘要和成本 4～14，再验证原始候选密码。匹配返回 true/nil，不匹配及无效候选（有效摘要下为空、非 UTF-8 或超过 72 字节）返回 false/nil；摘要格式/成本不受支持或其他 bcrypt 错误返回固定 domain.ErrInvalidPasswordHash，不携带敏感内容。当前种子账号成本为 12，不改变已有摘要。方法同步调用现有 bcrypt.CompareHashAndPassword，不重新生成摘要、不修改密码，也不承诺 context 可中断计算。此内部摘要错误不直接作为客户端凭证失败；登录服务的查询/状态/凭证错误编排随后实现，当前不注册登录路由。

第 021 小步已提供 CredentialService.Authenticate：注入现有账号查询方法，绑定 VerifyPassword，统一账号不存在/密码错误为 domain.ErrInvalidCredentials；未命中也使用固定非账号摘要执行一次成本 12 的比对，且不论是否匹配都拒绝认证，以减少明显快速失败差异，不承诺恒定耗时。密码匹配后才判断 ACTIVE/DISABLED，禁用返回 ErrAccountDisabled，未知状态、零 ID 或意外 nil 数据返回 ErrInvalidAccountData。成功仅返回 VerifiedAccount.ID，不携带摘要，不创建会话。查询故障保留错误链，摘要异常仍按内部故障处理；查询和同步比对前后检查请求取消，取消后不返回身份。当前仅测试装配，未注册 HTTP 登录路由；来源策略已在第 022 步实现，失败限流核心见第 023 步，HTTP 接入仍按后续小步进行。

JWT 采用固定算法 HS256，校验签名、issuer、audience、sub、sid 和 exp。签名密钥持久化，重启继续使用已有密钥。普通业务中间件查询会话和用户状态，关键写事务再复核撤销状态。

第 033 小步提供 NewAccessTokenSigner(jwtConfig)，与配置加载共用 JWTConfig.Validate，复制密钥并保存身份/有效期设置。Issue(session) 接收已提交会话，检查非零 ID，写入 iss/aud/sub/sid/iat/exp。sub/sid 为完整 uint64 十进制字符串，时间采用 UTC 整秒。exp 取签发时刻加 AccessTokenTTL 与会话到期时间的较早截止点，截止点已经不可用时返回 ErrSessionExpired。HS256 签名后返回 domain.AccessToken 的 Token/ExpiresAt。当前以签发器及测试入口验证，后续接入访问令牌校验与登录服务编排。

第 034 小步提供 NewAccessTokenVerifier(jwtConfig) 与 Verify(tokenText)。构造器共用配置校验并复制密钥，使用 MapClaims 按精确字段名读取声明，ParseWithClaims 固定 HS256，要求配置的 issuer/audience、exp 并检查 iat，采用严格 Base64URL 解码。项目进一步要求 iat/exp 存在且 exp 晚于 iat，sub/sid 是非零且无前导零的 uint64 十进制字符串。按服务器当前时间校验，单纯过期返回 ErrAccessTokenExpired，其他格式、签名及声明错误返回 ErrInvalidAccessToken，多项错误优先视为无效。成功返回 VerifiedAccessToken 的 UserID/SessionID/ExpiresAt，供后续查询用户及会话数据库状态。

登录限流首期使用有界内存记录，按来源 IP 与用户名分别计数，初始每分钟各 10 次失败尝试。清理过期记录并限制总条目数。第 023 小步已提供 LoginFailureLimiter.Begin：每个维度使用首次预留起 60 秒的固定窗口，失败数加在途预留最多 10；同时检查并预留两维，避免并发穿透。返回完成回调、建议等待或输入错误，完成回调幂等；只对 ErrInvalidCredentials 结算失败，其他结果释放预留但不清除已有失败。最多 4096 条有界键记录，容量不足拒绝而不驱逐未过期计数；按需清理到期失败并保留在途，无失败/在途的空记录即时释放。IP 使用 netip.Unmap 统一映射表示，用户名只接受规范小写 ASCII；第 024 步已提供 DirectPeerIP，只从 TCP RemoteAddr 解析真实连接 IP/非零端口并忽略所有转发头；LoginAttemptGate 注入共享 Begin 和凭证方法，在来源校验后申请名额并负责异常/取消兜底释放，受限不进入凭证查询。Handler 的 RateLimited 返回统一 429、RATE_LIMITED、details=null、no-store 和向上取整且至少为 1 秒的 Retry-After；允许的普通跨域响应额外暴露该头。此适配通过测试入口验证，尚未注册生产登录操作。该核心仅限单进程，重启清空，不是任意滚动 60 秒的严格上限；在途未结束时等待值不保证到期就可放行。

### 6.2 Web 与原生凭证交付

Web Access Token 存于页面内存，Refresh Token 通过 HttpOnly、SameSite=Strict Cookie 交付，路径限定为 /api/v1/auth。本机 HTTP 开发环境使用对应的 Cookie 配置，HTTPS 部署启用 Secure。

第 048 小步提供 handler.LoginSuccess(requestContext, result, profile, clientType, secureCookie)，输入须已通过登录字段、来源及服务校验。先检查响应状态和取消，再调用 NewLoginData 并预先编码 JSON。Web 刷新 Cookie 命名为 cloudnest_refresh_token，Path=/api/v1/auth，HttpOnly、SameSite=Strict，省略 Domain，Expires 采用会话 UTC 整秒截止时间。Cookie.Valid 成功且请求仍有效时写入 Cookie 及 JSON，返回 200、Cache-Control: no-store、Pragma: no-cache，并结束后续处理。Secure 由可信调用配置显式提供，HTTP 开发为 false，HTTPS 部署为 true。原生模式直接使用 JSON 中的刷新原文。转换、编码或 Cookie 校验失败使用统一 500，响应已提交时结束处理。当前通过测试专用入口与真实 HTTP/HTTPS Cookie Jar 验证，后续登录 Handler 复用本方法。

第 058 小步提供 handler.RefreshSuccess(requestContext, result, clientType, secureCookie)，输入须已完成请求/来源检查及刷新服务调用。先检查响应状态与取消，调用 NewRefreshData 并预先编码 RefreshResponse。登录与刷新共用 newRefreshCookie 构造方法，统一名称、认证路径、HttpOnly、SameSite=Strict、host-only 属性和会话 UTC 整秒 Expires，Secure 继续由可信配置传入。Cookie 校验通过且请求仍有效后，清理待发送的正文长度/编码头，设置 JSON、no-store 与 Pragma no-cache，按客户端模式写入 Cookie 及正文并结束后续处理。DTO、编码、Cookie 校验或取消错误沿用统一 500，响应已提交时结束处理。OpenAPI 提供共享 RefreshSucceeded 响应。测试路由已验证 HTTP/HTTPS Cookie Jar 替换新值、路径/主机/Secure 范围、真实 JWT、失败与两次取消边界，并回归现有登录交付。

第 049 小步提供 handler.Login(policy, authenticate, createTokens, getProfile, secureCookie)，各方法分别绑定共享 LoginAttemptGate.Authenticate、LoginTokenService.Create 和 UserProfileService.Get。执行顺序为有上限 JSON/字段校验、来源校验、限流与凭证验证、用户资料读取及 DTO 可表示性检查、会话/令牌创建、LoginSuccess 交付。资料错误在会话创建前结束，请求上下文贯穿各阶段并在调用后复查取消。错误凭证使用 AUTH_REQUIRED 401 和固定“用户名或密码错误”，限流使用既有 429，账号禁用沿用 403，其余未知故障沿用 500。当前通过测试端点验证，包含真实 bcrypt、共享限流、JWT 与 TCP 的组件联测，实际登录操作由后续启动装配接入。

第 050 小步将 POST /api/v1/auth/login 接入生产启动流程。启动读取 CLOUDNEST_COOKIE_SECURE，构造一份 CredentialService、LoginFailureLimiter 和 LoginAttemptGate，再复用 JWT 配置构造签发器、LoginSessionService 与 LoginTokenService。事务适配回调继续使用同一 txContext/txStore。RegisterLoginRoute 挂载已有 Login 处理函数，来源策略使用同一前端白名单。完整生产 run 测试采用成本 12 的 bcrypt 测试账号、正式迁移隔离库和已有 MinIO，验证 Web/原生真实登录、刷新摘要、登录后 /me、设备复用、重启、撤销恢复及共享失败限流，完成后清理测试库。

Web 刷新、登录和退出请求检查 Origin 白名单，并要求自定义 X-CloudNest-Client: web 请求头。凭证型 CORS 使用明确 Origin，跨站预检被拒绝。允许的请求头包括 Authorization、Content-Type、Idempotency-Key、X-CloudNest-Client 和 X-Request-ID。第 016 步已实现全局 CORS，预检支持 GET、HEAD、POST、PUT、PATCH、DELETE、OPTIONS；合法预检仅表示策略许可，不验证具体路径是否实现。不带预检方法头的 OPTIONS 沿用普通路由，显式空或非法的预检头拒绝；不设置预检缓存时长。第 022 小步已提供独立 LoginSourcePolicy：登录正文 client_type 与单个 X-CloudNest-Client 必须精确相同；web 另需单个白名单 Origin，native 则必须无 Origin。策略放在 DTO 校验后、凭证查询前，违规返回 CLIENT_SOURCE_FORBIDDEN 403，不回显请求内容。全局 CORS 先拒绝的未知 Origin 仍为 CORS_FORBIDDEN；合法预检不进入登录来源检查。当前通过测试专用入口验证，不改变系统 GET；登录、刷新与退出的实际 Handler 按对应步骤接入。

原生客户端登录要求 X-CloudNest-Client: native 且不带 Origin；若使用自动附带 Origin 的 WebView 网络层，应改用匹配方案的原生 HTTP 通道，不能直接跳过检查。该声明不证明程序身份，仍需验证凭证。原生客户端通过 JSON 获得 Refresh Token 并保存在系统安全存储。刷新请求在 JSON 中提交令牌，原生模式使用令牌载荷交付，Web Cookie 路径仅由 Web 模式处理。出现未知 Origin 的浏览器请求统一拒绝。

第 059 小步提供 dto.RefreshRequest 的 client_type、refresh_token 及 Validate()。客户端类型精确为 web/native，Web 正文中的刷新原文须为空，原生原文须为非空字符串，字段校验按客户端类型优先返回固定 FieldError。沿用 JSON 读取器和 Go 字符串字段的空值规则，Web refresh_token 省略、空字符串或 null 均作为空值处理，原生这三类输入均返回 refresh_token 字段错误。原文保持输入值，后续 RefreshCredentialService 负责规范 Base64URL、摘要和状态校验。OpenAPI 以两个 oneOf 分支表达请求组合，测试路由已组合 ReadJSON、Validate 和 InvalidArgument 验证输入、错误定位及日志。

第 060 小步提供 security.RefreshToken(request, input)，输入为 HTTP 请求与已校验 RefreshRequest，调用方先完成来源检查。入口复查非 nil 请求和 DTO 组合，原生模式直接返回正文原文。Web 遍历所有 Cookie 头中的同名原始项计数，要求恰好一项，再用 Request.CookiesNamed 解析并要求得到单个非空值。原始计数覆盖标准解析器可能跳过的无效同名项，重复或解析失败均返回空字符串及 ErrInvalidRefreshToken。Cookie 名称集中在 security，交付层常量引用该值。AuthorizationFailure 将直接或包装的 ErrInvalidRefreshToken 映射为 AUTH_REQUIRED 401，附带既有 Bearer 提示、no-store、details=null 与请求 ID。测试路由已组合 JSON/字段/来源检查、提取、真实凭证格式与摘要校验，核对 400/403/401 顺序及原文保护。

第 070 小步将 POST /api/v1/auth/logout 接入正式启动。main.run 复用 Store，通过 WithUserTransaction 的同一 txContext/txStore 回调装配 LogoutService。RegisterLogoutRoute 绑定已有授权服务、来源白名单及 Cookie 配置，按 RequireAuthorization、handler.Logout 的顺序注册正式路径。OpenAPI 使用 BearerAuth、LogoutRequest、LogoutSucceeded 和共享来源参数。真实 run 集成测试采用正式迁移独占库、临时配置目录、空闲端口与已有 MinIO，验证两轮启动中的 Web/原生退出、数据库撤销状态、刷新后的凭证失效、同设备另一会话可用、重启后撤销持续及 Cookie Secure 配置，沿用既有关闭、日志和清理检查。

每个客户端对刷新执行 single-flight。轮换使用旧摘要和 token_generation 条件更新，成功后旧刷新值失效。刷新响应丢失时重新登录。退出撤销会话，并清理 Web Cookie 或原生本地凭证。

第 052 小步提供 RefreshCredentialService.Verify(ctx, rawToken)，绑定 FindRefreshSession。原文须为 32 字节数据的规范无填充 Base64URL，长度为 43，Strict 解码后复编码须与原文一致。摘要按原始编码文本计算。格式错误与摘要未命中统一为 ErrInvalidRefreshToken，数据库故障保留原因。查询后检查取消，校验非零标识、代次和期限，再按账号、会话撤销、设备撤销与会话截止时间顺序判断。成功返回 VerifiedRefreshSession 的 LoginSession、TokenGeneration 与 json:"-" 的 TokenHash。会话有效期按查询后的当前时间检查，轮换写入继续在事务内复查当前摘要、代次与状态。

## 7. 目录和偏好规则

名称规则与数据库方案共用样例，按 NFC → case folding → NFC 生成 UTF-8 名称键。显示名最多 120 个 UTF-16 代码单元，归一化键最多 768 字节。空名、路径字符、控制字符及保留设备名在 Service 中校验。

创建目录、重命名和移动遇到活动名称冲突返回 NAME_CONFLICT。上传和恢复采用后缀命名策略，扩展名保留在末尾，必要时截短基名以满足长度上限，结果返回最终名称。

每个文件或目录操作校验 user_id、自己的生命周期、全部祖先、父目录类型及权限。移动额外验证目标不在自身子树，深度最多 32，目标移动后的后代深度也需满足限制，操作子树最大 10000 项。

expected_revision 在持锁事务中比对。内容、名称、位置或回收状态变化时 revision 加一并更新时间。收藏与访问记录写入偏好表，文件 revision 保持其业务修改含义。

目录列表读取使用一致性数据库快照完成父链与条目查询。授权下载的权限判断对应签名时刻，签名 URL 有效期内持有者可以读取对应不可变对象。

## 8. 小文件上传闭环

### 8.1 创建与接收

1. POST /uploads 校验名称、大小、目标目录和来源设备，在用户事务中检查配额并预占完整文件大小。
2. 创建 STAGING 对象记录及 SINGLE 上传任务，生成随机对象键，任务进入 UPLOADING。幂等结果与任务同事务写入。
3. 客户端向 content_path 发送原始文件流。服务端在用户事务中领取该任务租约，递增 lease_version，持有有效租约的并发请求返回 UPLOAD_BUSY。
4. 请求体流式写入应用临时文件，同时计算 SHA256 和实际字节数。限制为声明大小加一个检测字节，并受 16 MiB 上限及传输总时限约束。
5. 核对实际大小，客户端提供 sha256 时同时比较。随后从已稳定的临时文件写入当前 staged_object_id 对应的对象键。
6. 存储写入返回后，以 task_id、status、lease_version 和 staged_object_id 为条件进入 VERIFYING，释放接收租约并交给校验 worker。
7. PUT 返回 202，前端展示“校验中”，轮询任务结果。

临时文件使用应用专属目录与随机尝试标识，文件名由服务端生成。初始最大并发接收数为 3，临时区容量上限为 128 MiB。失败和退出后通过归属清晰的临时文件清理流程回收空间。

接收过程使用 http.MaxBytesReader 等手段限制实际读取量，并将请求取消传递给临时文件处理和存储调用。[Go HTTP 请求体限制](https://pkg.go.dev/net/http#MaxBytesReader)

### 8.2 上传重试与不可变写入

首次写入使用任务当前的 staged_object_id。任务进程崩溃或响应丢失后，恢复流程先检查该对象是否完整存在，存在且大小、哈希符合时继续校验发布。

确需重新接收内容时，在用户事务内取得新租约，创建新的 STAGING 对象并更新 staged_object_id，旧对象进入 ORPHANED。新尝试拥有独立对象键，旧请求的迟到写入只影响旧尝试的对象。所有后续数据库回写必须匹配当前租约和对象 ID。

任务在一个时间点仅保留一个当前 staged_object_id。已替换的暂存对象通过自身状态与清理时间继续管理。签名及长期对象键保持不可复用原则。

### 8.3 校验、去重与发布

校验 worker 领取 VERIFYING 租约，在事务外读取存储对象并重新计算大小和 SHA256。校验结果只对当前 staged_object_id 及租约版本有效。

发布事务依次完成以下动作。

1. 锁定用户，复核账号、任务、目标目录和祖先状态。
2. 按同用户哈希与大小查找 READY 对象。存在可复用对象时引用它，暂存副本进入 ORPHANED，否则把本次对象推进 READY。
3. 在用户锁内选择可用上传名称，生成符合长度限制的后缀。
4. 创建 FILE 目录项，写入对象 ID、大小快照、来源设备和内容时间。
5. 将任务 reserved_bytes 转入 used_storage，预占归零。
6. 写入 published_object_id、result_entry_id、resolved_name、completed_at，任务进入 COMPLETED。
7. 新建内容引用的对象清空 unreferenced_at 与 gc_after。

目标目录失效时终止发布并释放预占，返回 TARGET_UNAVAILABLE。同名上传按批准的后缀策略处理。校验失败进入 FAILED 并释放预占，暂存内容进入延迟清理。

### 8.4 取消与幂等完成

完成请求只推动已有任务。UPLOADING 且内容尚不完整时返回 TASK_NOT_READY，VERIFYING 返回 202，COMPLETED 返回已保存的结果 ID。

取消请求将可取消阶段转入 CANCELLING，随后终结为 CANCELLED 并将 reserved_bytes 归零。过期流程对应 EXPIRING → EXPIRED。完成、取消和过期在同一用户锁及任务条件更新下竞争，终态重试复用已记录结果。

临时网络失败记录 next_attempt_at 和 last_error_code，任务保持可恢复状态。目标失效、大小不符、校验失败等业务错误按明确规则结束任务。

## 9. 下载与预览

POST /entries/{id}/download 验证会话、文件归属、祖先可见性和 expected_revision，再确认对应物理对象为 READY。存储对象缺失或不可用时返回明确错误并记录核对任务线索。

签名固定到不可变 object_id 和对象键，有效期初始为 15 分钟，响应包含对象身份、版本、字节数和已验证 SHA256。URL 过期后需要重新鉴权，同一下载任务继续绑定原对象。原内容已经无权访问时结束续传。

首期下载采用短期 S3 GET URL，存储提供 Range 能力。客户端对 200、206、416 和对象身份变化分别处理。前端通过 download 返回的名字生成下载行为，文件名使用规范 Content-Disposition 编码。

预览初期覆盖已校验 MIME 的常见栅格图片和大小不超过 2 MiB 的纯文本。纯文本由界面转义渲染。浏览器可支持的 PDF 和视频预览在对应前端阶段验证后开放。其他格式提供下载。

purpose=download 或成功授权的预览访问记录 last_opened_at，最多每 60 秒合并一次。该时间表示获得访问授权的时刻。

## 10. 回收站与永久清理

### 10.1 回收与恢复

回收将被选根项改为 TRASHED，保留 parent_id、对象引用和配额占用。后代在所有正常列表及授权流程中按祖先状态隐藏。

恢复在用户锁内确认原父目录是否可访问。有效则恢复至原位置，失效则选择真实根目录。名称冲突自动增加后缀，响应给出实际位置和名称。文件偏好保留，恢复后重新进入有效收藏和最近使用候选。

批量操作先移除选择集合中已被选中祖先覆盖的后代。每个顶层项独立返回结果，部分失败时保留准确状态。

### 10.2 永久清理

清理请求验证预检摘要、expected_revision、归属和范围，原子标记 PURGING。该状态让子树立即不可访问，返回 202 和稳定的根目录项 ID 供查询。

worker 每次在用户事务中选取最多 100 个可处理叶子。对每个尚未 PURGED 的 FILE 释放逻辑空间、清空 object_id、删除偏好并写入 purged_at。DIR 在后代处理完成后终结。事务回滚保持该批原状，重启后继续扫描持久状态。

被清理目录内此前已独立回收的后代计入预检范围。PURGED 墓碑按数据库保留期和引用约束进行后续清理。

### 10.3 对象 GC

逻辑引用释放后，在用户事务中检查对象是否仍被正常文件、回收站、清理中后代、非终态任务或后续历史版本引用。确认失去最后引用时写入 unreferenced_at，gc_after 设为 7 天后。

到期 worker 再次锁定用户和对象，检查当前全部有效引用并条件转为 DELETING。随后在事务外删除存储对象，成功或确定对象已不存在后标记 DELETED。失败保留 DELETING 并周期重试。

READY 或 ORPHANED 对象状态改变后，dedup_hash 由数据库生成列更新。新引用只能指向 READY 对象，并与 GC 使用相同用户锁，避免新引用和删除交错。

## 11. 后台任务、重试与观测

### 11.1 首期任务安排

| 任务 | 初始频率与并发 | 持久依据 |
|---|---|---|
| 上传校验与恢复 | 每 5 秒扫描，1 个校验 worker | upload_tasks 状态、next_attempt_at、lease_version |
| 上传取消与过期 | 每 30 秒扫描，最多 100 项 | status、expires_at、reserved_bytes |
| 回收站到期标记 | 每小时扫描，最多 100 个根项 | TRASHED 和 deleted_at |
| 子树永久清理 | 每 5 秒扫描，每事务最多 100 项 | PURGING/PURGED |
| 孤儿对象与 GC | 每分钟扫描，初始并发 1 | status、unreferenced_at、gc_after |
| 会话及幂等记录过期清理 | 每小时小批执行 | expires_at、revoked_at |
| 配额核对 | 每日及恢复维护窗口 | 未 PURGED 文件、保留版本与任务预占 |
| 临时文件回收 | 启动时及每小时 | 应用目录内的归属标识和任务状态 |

任务频率均可配置。目录批处理只进行短数据库事务，同账号锁协调并发执行。涉及长存储 I/O 的上传任务领取租约，初始期限 60 秒，每 20 秒续约，写回时要求租约仍有效且版本匹配。

对象 DELETING 状态充当清理意图。物理删除按固定对象键幂等执行，多个恢复执行者即使重叠也只能处理同一不可变对象。

### 11.2 重试边界

瞬时网络失败采用有限指数退避，初始 1 秒，最高 30 秒，每轮最多 5 次。超过本轮次数后写入下次恢复时间，由持久任务再次调度。

数据库死锁只重试包含纯数据库动作的完整事务回调，初始最多 3 次。幂等键及事务结果同时处理，外部存储操作依赖持久阶段，重试时重新核对其状态。

客户端断连取消当前接收和短请求。已持久化的校验、取消及发布恢复由 worker 接管，客户端可以通过任务 ID 继续查询。

### 11.3 日志与状态

日志至少包含 request_id、user_id、session_id、task_id、object_id、阶段、耗时和错误码。密码、Access/Refresh Token、签名 URL 查询参数和文件内容从日志排除。

第 012 小步已实现 HTTP 完成日志，字段为 request_id、method、path、status、duration_ms，并沿用时间、级别与服务名；其他业务字段随后续功能接入。NewRouter 接收入口日志对象，显式采用 RequestID → RequestLog → Recovery → CORS 顺序；Recovery 禁止原始请求和 panic 转储，日志在恢复完成后记录最终状态。普通请求的 2xx/3xx 为 INFO、4xx 为 WARN、5xx 为 ERROR；第 014 小步增加普通恢复异常的 recovered_panic=true 标记，即使响应已提交而实际 status 小于 500，仍使用 ERROR。path 仅取 URL.Path，不记录查询、请求头、正文、c.Errors 或 panic 载荷；替换默认文本访问日志，避免重复输出。

首期记录请求错误率、数据库耗时、任务积压、校验耗时、重试次数、临时空间、GC 失败和配额差异。关键任务失败能在上传结果或运维日志中定位。

开发模式只信任直接来源，部署反向代理时显式配置可信代理和 Origin。JSON 参数和错误响应保持统一脱敏规则。

## 12. 前端接入约定

### 12.1 前端数据适配

建议增加 api/http.ts 处理认证、刷新和统一错误，api/drive.ts 封装业务接口。Demo 数据和真实 API 通过明确的数据模式配置选择，界面状态由对应数据源驱动。

### 12.2 登录与页面状态

首次接入增加登录界面，使用已初始化的业务 root 账号。页面刷新时通过 Web 刷新凭证恢复会话，再获取 /me 和根目录。

列表页面支持加载中、空列表、加载失败和部分批量失败。删除完成后刷新列表及空间信息。上传阶段为 VERIFYING 时显示“校验中”，COMPLETED 后使用 result_entry_id 读取真实文件并更新列表。

浏览器上传进度优先用 XMLHttpRequest 的上传事件，控制接口采用 fetch。SINGLE 暂停在首期表现为中止当前发送并保留任务，继续时整文件重传。Multipart 阶段才提供按分片续传。

### 12.3 本机开发访问

建议 Vite 将 /api 代理到 127.0.0.1:18081，使 Web Cookie 和控制接口采用同一页面来源。后端仍校验前端 Origin 白名单，避免开发代理放宽业务授权。

MinIO 下载属于独立端口来源，配置仅覆盖已验证用途所需的 CORS。分片直传上线时再验证 PUT、校验请求头和 ETag 暴露。
