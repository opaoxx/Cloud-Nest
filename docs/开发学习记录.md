## 第 001 步——读取并校验后端监听地址

完成日期为 2026-11-04，所属阶段为 B0 服务基础。

### 本次目标

启动服务需要一个监听地址，例如 127.0.0.1:18081。本次将地址读取与校验放入 config 包，main 调用它获得结果后启动服务。

方法的输入来自环境变量 CLOUDNEST_HTTP_ADDR，输出为监听地址和 error。变量未设置或为空时使用 127.0.0.1:18081，格式或端口错误时返回原因。

### 文件与调用关系

| 文件 | 职责 |
|---|---|
| internal/server/config/http.go | LoadHTTPAddress 按步骤读取和校验配置 |
| cmd/server/main.go | 获取配置，错误时结束启动，成功时注册路由并监听 |
| internal/server/config/http_test.go | 对正常、错误和边界输入执行验证 |

~~~text
go run ./cmd/server
  → main()
    → config.LoadHTTPAddress()
      → 读取环境变量或采用默认值
      → 拆分 host 和 port
      → 检查数字端口及项目保留端口
      → 返回地址或错误
    → 注册 /ping
    → router.Run(listenAddress)
~~~

### 按注释理解代码

1. os.Getenv 读取环境变量，空值时采用默认值。
2. net.SplitHostPort 拆分地址。比如 127.0.0.1:18081 会得到主机 127.0.0.1 和端口文本 18081，IPv6 使用方括号写法。
3. strconv.ParseUint 把端口文本转换成数字，16 位范围上限为 65535，再排除 0。
4. 检查项目保留的 8080～8090 和 18080，避免误用其他项目的端口。
5. net.JoinHostPort 将主机与数字端口组合为地址，确保 IPv6 方括号及端口格式一致。

当方法返回错误时，main 输出原因并结束启动。配置包负责提供地址，main 负责启动服务。实际端口占用及主机名解析由后续监听操作报告。

## 第 002 步——初始化后端启动日志

开始日期为 2026-11-04，所属阶段为 B0 服务基础。

### 编码前的小方案

目标是让配置读取与 HTTP 启动使用统一格式记录结果。使用 Go 标准库 log/slog，不引入新依赖。

- 模块边界：新增 internal/server/logging，负责创建日志对象；cmd/server/main.go 负责调用与启动流程。
- 输入和输出：logging.New 接收 io.Writer（输出位置），返回 *slog.Logger（日志对象）；main 传入 os.Stdout，日志显示在终端。
- 日志字段：time、level、msg 和固定的 service=cloudnest-api；配置成功附加 address，失败附加 stage 和 error。
- 调用顺序：main → logging.New → config.LoadHTTPAddress → 注册路由 → 记录准备启动 → router.Run；错误时记录 ERROR 后以状态码 1 退出。
- 为了记录配置错误，先初始化固定格式日志，再读取 HTTP 配置。准备启动日志表示监听尝试开始，服务是否可响应通过 /ping 确认。
- 本步接口契约仍为既有 GET /ping，无数据库表、缓存、消息或跨服务契约变动。Gin 自带访问日志和调试输出仍按现有方式输出，统一请求日志在后续中间件步骤完成。
- 验证策略：格式化、Go 测试和静态检查；实际启动并请求 /ping，解析 JSON 日志字段；验证保留端口配置及端口占用时的错误日志与退出码。
- 提交策略：完成本步验证后交付，由用户决定 Git 提交。

初始化方法先写以下步骤注释，再填入对应实现：

~~~go
// 1. 创建 JSON 日志处理器，将日志写入指定位置。
// 2. 创建日志对象，统一附加服务名称。
// 3. 返回日志对象，交给启动入口使用。
~~~

### 按调用顺序理解代码

| 文件 | 本次职责 |
|---|---|
| internal/server/logging/logger.go | 创建统一的 JSON 日志对象 |
| cmd/server/main.go | 使用日志对象记录配置结果、启动尝试和启动失败 |

1. main 把 os.Stdout 传给 logging.New，表示日志输出到终端。io.Writer 是 Go 对“可以接收写入内容的对象”的约定；将来需要输出到文件时，也可以传入文件对象。
2. NewJSONHandler 决定日志按 JSON 格式输出，最低级别设为 INFO；因此 INFO 和 ERROR 都会记录。slog.New 创建日志对象，With 附加固定服务名。
3. main 调用上一小步的 LoadHTTPAddress。成功记录 INFO 与 address，失败记录 ERROR、stage=config 与 error，再用 os.Exit(1) 告诉操作系统启动失败。
4. 注册现有 /ping 路由后，先记录准备启动，再调用 router.Run。端口占用等实际监听错误由 Run 返回，入口记录 stage=http、address 和 error 后退出。

例如下面是一条配置成功日志，实际时间以运行结果为准：

~~~json
{"time":"2026-11-04T20:00:00+08:00","level":"INFO","msg":"HTTP 监听配置读取成功","service":"cloudnest-api","address":"127.0.0.1:18081"}
~~~

msg 是人读的消息，address 等独立字段方便查找和筛选。当前只记录启动流程涉及的字段；请求 ID、用户 ID 和任务 ID 随后续功能接入时补充。

### 运行与验证

在项目根目录执行：

~~~powershell
go run ./cmd/server
~~~

终端可看到配置成功与准备启动两条 JSON 日志，以及 Gin 原有的调试输出。另开终端请求：

~~~powershell
Invoke-RestMethod http://127.0.0.1:18081/ping
~~~

返回 message 为 CloudNest API is running。用 Ctrl+C 停止服务后，可以验证配置失败：

~~~powershell
$env:CLOUDNEST_HTTP_ADDR = '127.0.0.1:8085'
go run ./cmd/server
Remove-Item Env:CLOUDNEST_HTTP_ADDR -ErrorAction SilentlyContinue
~~~

应看到 level=ERROR、stage=config 和保留端口原因。go run 还会报告 exit status 1。

- 使用临时 socket 独占另一个临时端口，再启动服务，确认记录 HTTP ERROR、地址和系统错误，进程退出码为 1。
