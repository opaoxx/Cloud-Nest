# CloudNest 数据库设计方案书

版本 v1.1，编写日期 2026-11-04，方案已获用户批准，首期结构已实施。

本方案依据项目技术方案 v2.0 和已体验的 Web Demo 编写。首期八张业务表、迁移记录和账号根目录已落地，数据库级约束及 SQL 事务验证通过。业务 Service、Repository 和 API 集成按后续开发阶段推进。

## 1. 目标与现状

2026-11-04 通过只读查询确认，本机 MySQL 为 8.4.13，cloudnest 库当前业务表数量为 0，服务端字符集为 utf8mb4。MinIO 环境中的 cloudnest Bucket 沿用已完成的基础设施配置。

| 系统 | 本阶段职责 |
|---|---|
| MySQL | 账号、设备、会话、目录树、文件引用、收藏和最近打开、上传任务、配额和幂等结果 |
| MinIO | 不可变文件内容和未完成 Multipart 数据 |
| 浏览器及未来客户端本地存储 | 上传/下载队列的本机进度、源文件授权、下载偏移 |
| Redis | 保留基础设施，业务设计暂缓接入 |

用户文件名、目录移动、收藏和回收站操作通过 MySQL 元数据表达。实际文件内容通过 stored_objects 中的存储位置定位。文件路径发生变化时继续引用同一物理对象。

### 1.1 评审建议默认值

| 决策 | 建议值 | 影响 |

| 文件内容去重 | 同账号、SHA256 与大小一致、已验证内容 | 每个逻辑副本分别占配额 |
| 回收站保留期 | 30 天 | 回收站文件继续占用配额 |
| 对象清理宽限期 | 连续无有效引用满 7 天 | 覆盖最长签名 URL 有效期 |
| 同目录重名规则 | 统一名称归一化后大小写不敏感 | 文件与文件夹共用名称空间 |
| 最近使用 | 最近成功授权打开/预览/下载 | 与最近修改分别记录 |
| 恢复冲突 | 自动增加后缀，原父目录失效时恢复到根目录 | 与 Demo 的体验保持一致 |

本节参数已获批准。初始账号配额已写入数据库，保留期、名称后缀及目录操作上限由后续业务实现执行。真实可用空间还受本机磁盘和对象存储容量约束。

## 4. 通用字段与数据库规则

- 存储引擎统一 InnoDB，业务表使用 utf8mb4。名称判重使用单独的二进制归一化键。
- 实体主键使用 BIGINT UNSIGNED 自增。对外所有 ID 使用字符串序列化。
- 字节数采用 BIGINT UNSIGNED，时间采用 DATETIME(6)，数据库连接和服务端统一 UTC。
- created_at、updated_at 为可变实体的公共字段，默认 CURRENT_TIMESTAMP(6)。应用在修改时更新 updated_at，业务修改时间单独定义。
- 固定枚举使用 VARCHAR 加 CHECK 约束，迁移时明确变更允许值。
- SHA256 在库内使用 BINARY(32)，API 使用 64 位小写十六进制。其他校验值同时保存算法。
- 外键删除和更新默认 RESTRICT，删除行为通过业务事务处理。
- 登录密码使用 bcrypt 摘要，Refresh Token 使用随机高熵值并保存 SHA256 摘要。
- MinIO 长期凭证来自服务端配置。对象记录保存 provider、bucket、object_key 和可选版本定位。
- 数据库默认隔离级别沿用 REPEATABLE READ。关键写操作显式锁行，权限和状态检查使用当前读。

CHECK 对单行条件进行校验，跨记录的父目录类型、祖先可见性、对象状态和配额汇总通过事务验证。涉及可空字段的条件显式处理 NULL。[MySQL CHECK 文档](https://dev.mysql.com/doc/refman/8.4/en/create-table-check-constraints.html)

DDL 使用外键默认的限制删除语义，省略显式引用动作子句。CHECK 涉及的外键列及生成列基列列入专项兼容验证，确保最终约束组合符合 MySQL 8.4 的限制。

## 5. 首期数据字典

以下表中 NN 表示必填，NULL 表示可空。公共时间字段按第 4 节约定处理。表格为评审用字段规格，实施阶段据此生成完整 DDL 和字段 COMMENT。

### 5.1 users

| 字段 | 类型 | 空值与默认 | 业务含义 |
|---|---|---|---|
| id | BIGINT UNSIGNED | NN，自增 PK | 用户 ID |
| username | VARCHAR(64) | NN | 归一化后的登录名，限定小写 ASCII 字母、数字、下划线 |
| display_name | VARCHAR(64) | NN | 用户展示名称 |
| password_hash | VARCHAR(255) | NN | bcrypt 密码摘要 |
| status | VARCHAR(16) | NN，ACTIVE | ACTIVE 或 DISABLED |
| storage_quota | BIGINT UNSIGNED | NN，107374182400 | 逻辑配额 |
| used_storage | BIGINT UNSIGNED | NN，0 | 已发布文件、回收站和后续保留版本的逻辑用量 |
| reserved_storage | BIGINT UNSIGNED | NN，0 | 未结束上传任务预占 |
| change_seq | BIGINT UNSIGNED | NN，0 | 后续同步阶段的用户变更序号 |
| created_at、updated_at | DATETIME(6) | NN | 创建与更新 |

唯一索引 uk_users_username(username)。服务端事务保证 used_storage + reserved_storage <= storage_quota，调低配额也遵循该条件。

开发账号建议初始化为 root，密码按用户约定使用 root，经 bcrypt 后落库。数据库连接账号与业务账号分别管理，初始化时显式创建业务账号。

### 5.2 user_devices

| 字段 | 类型 | 空值与默认 | 业务含义 |
|---|---|---|---|
| id | BIGINT UNSIGNED | NN，自增 PK | 设备 ID |
| user_id | BIGINT UNSIGNED | NN，FK | 所属用户 |
| installation_id | CHAR(36)，ASCII | NN | 客户端生成并持久化的安装 UUID |
| name | VARCHAR(100) | NN | 用户可修改的设备名称 |
| platform | VARCHAR(16) | NN | WEB、WINDOWS、ANDROID，未来扩展鸿蒙 |
| os_version、app_version | VARCHAR(64) | NULL | 展示和故障定位信息 |
| last_seen_at | DATETIME(6) | NULL | 最近认证活动 |
| revoked_at | DATETIME(6) | NULL | 设备撤销时间 |
| created_at、updated_at | DATETIME(6) | NN | 创建与更新 |

唯一索引 (user_id, installation_id) 和 (user_id, id)。普通索引 (user_id, last_seen_at, id)。

浏览器清理本地安装标识后可形成新设备记录。在线状态由最近活动推算，界面展示“最近活跃”。设备撤销保留历史记录，引用它的文件仍能显示原始来源。

用户于 2026-11-11 确认设备重新登录规则。账号密码重新验证通过后，复用原设备 ID，并在用户事务内清空该设备 revoked_at、更新 updated_at。既有会话的撤销状态由 auth_sessions.revoked_at 独立保留，重新登录随后创建新的会话。已有设备名称和平台沿用当前记录。

### 5.3 auth_sessions

| 字段 | 类型 | 空值与默认 | 业务含义 |
|---|---|---|---|
| id | BIGINT UNSIGNED | NN，自增 PK | JWT 中 sid 对应的会话 |
| user_id、device_id | BIGINT UNSIGNED | NN，FK | 用户和设备归属 |
| refresh_token_hash | BINARY(32) | NN | 当前有效 Refresh Token 摘要 |
| token_generation | BIGINT UNSIGNED | NN，1 | 刷新轮换代次 |
| expires_at | DATETIME(6) | NN | 会话刷新期限 |
| last_seen_at | DATETIME(6) | NULL | 最近会话使用 |
| revoked_at | DATETIME(6) | NULL | 会话撤销时间 |
| created_at、updated_at | DATETIME(6) | NN | 创建与更新 |

唯一索引 refresh_token_hash，普通索引 (user_id, device_id, revoked_at) 与 expires_at。复合外键 (user_id, device_id) 引用 user_devices(user_id, id)。

刷新以旧摘要和代次为条件原子轮换。响应丢失导致新令牌未被客户端收到时要求重新登录。客户端刷新请求实行 single-flight。设备撤销与其会话撤销同事务提交。

### 5.4 stored_objects

| 字段 | 类型 | 空值与默认 | 业务含义 |
|---|---|---|---|
| id | BIGINT UNSIGNED | NN，自增 PK | 物理对象 ID |
| owner_user_id | BIGINT UNSIGNED | NN，FK | 所属账号 |
| provider | VARCHAR(32)，ASCII | NN | 存储配置逻辑标识，如 local_minio |
| bucket | VARCHAR(63)，ASCII | NN | Bucket 名称 |
| object_key | VARCHAR(255)，ASCII binary | NN | 服务端生成的不可变对象键 |
| storage_version_id | VARCHAR(255)，ASCII | NULL | 存储开启版本化时的定位信息 |
| file_size | BIGINT UNSIGNED | NN | 初始化预期大小，发布前必须与实际值一致 |
| verified_sha256 | BINARY(32) | NULL | 服务端验证后的哈希 |
| dedup_hash | BINARY(32)，生成列 | NULL | READY 状态下取 verified_sha256，其他状态为 NULL |
| storage_etag | VARCHAR(255)，ASCII | NULL | 存储返回的不透明 ETag |
| status | VARCHAR(16) | NN，STAGING | 见第 8 节 |
| verified_at | DATETIME(6) | NULL | 内容校验完成时间 |
| unreferenced_at、gc_after | DATETIME(6) | NULL | 连续失去有效引用的起点与清理时间 |
| last_error_code | VARCHAR(64)，ASCII | NULL | 恢复和清理错误码 |
| created_at、updated_at | DATETIME(6) | NN | 创建与更新 |

唯一索引 (provider, bucket, object_key)、(owner_user_id, id)、(owner_user_id, dedup_hash, file_size)。扫描索引 (status, gc_after, id)。

READY 必须同时具备 verified_sha256 和 verified_at。同账号同内容上传竞争唯一键时，复用已存在的 READY 对象，另一个暂存对象进入 ORPHANED。

第 276 步 MarkUserStagedObjectOrphaned 在已认证用户事务内以当前读锁定完整对象及引用范围，拒绝仍有未 PURGED 文件或未终结任务的内容引用。支持 STAGING 到 ORPHANED，并为历史缺少回收计时的 ORPHANED 记录补齐起点。首次无引用标记使用同一条 SQL 的 UTC_TIMESTAMP(6) 写 unreferenced_at、gc_after=起点加七天及 updated_at，已计时记录重复调用保留原期限。终态上传记录的审计外键继续保留，任务引用替换和旧对象孤立标记由同一外层事务确认。真实 MySQL 已验证有效引用阻止、当前读、七天期限、重复/并发、双表提交/回滚及完整 BIGINT UNSIGNED 范围。

第 252 步以 domain.StoredObjectStatus 表达 stored_objects.status 的六个合法值，IsValid 精确匹配大小写及完整文本。专项从嵌入的正式迁移提取 ck_objects_status 和默认 STAGING，对照领域状态并连续三次通过。READY 的哈希及验证时间要求、清理时间成对约束由后续完整记录校验及事务落实。

第 253 步 domain.StoredObject 覆盖本表十七列，八个 NULL 列以指针保留缺失语义。verified_sha256 和 dedup_hash 分别使用 *[sha256.Size]byte，状态复用精确类型。dedup_hash 作为数据库生成列的读取值保留，后续 GORM 映射标记只读。正式迁移的列名、类型、空值与生成列对照连续三次通过，暂存对象可用完整无符号主键与所属任务关联，客户端预期摘要保存在任务中，服务端已验证摘要由后续校验流程写入。

第 254 步 models.StoredObject 对本表十七列建立显式只读查询映射，包含只读生成列 dedup_hash。GORM 解析核对列名、读取权限及领域类型衔接，摘要使用可空 []byte，状态保留原文。SQL 测试连接器扫描十四组结果连续三次通过，核对 NULL、完整 BIGINT UNSIGNED、摘要与日期原值及异常扫描，后续读取在 owner_user_id/id 范围内检查并转换独立领域记录。

第 255 步 FindUserStoredObject 在 owner_user_id/id 范围显式读取十七列，保留六种合法生命周期记录。领域转换核对 READY 的验证事实与 dedup_hash，其他状态生成值为空，回收时间与 ck_objects_gc 对齐，并校验 UTC 微秒时间及数据库年份。八个可空结果独立复制。正式表独占库联测连续三次验证实际生成列、用户隔离、零字节/NULL、外部写锁期间的已提交读取、完整无符号 ID/大小及日期边界，验证库沿用既有自动清理和清理复核。

第 312 步 FindReusableUploadObject 在用户事务内按 owner_user_id、dedup_hash、file_size 及 READY 状态查询，读取并锁定唯一匹配行。回收计时中的 READY 对象仍可被查询，新增引用时清理计时由后续发布事务完成。正式 MySQL 核对同摘要不同大小、零字节、其他账号、非 READY 及候选锁保持。

第 313 步 PromoteVerifiedUploadObject 联合当前 upload_tasks 和 stored_objects 条件更新对象。条件覆盖所有权、当前暂存对象、大小、存储位置、可空版本与 ETag、校验租约持有者及版本。更新再次要求租约和任务到期时间均晚于本条语句的 UTC_TIMESTAMP(6)，将状态改为 READY、写入实测摘要，用同一个数据库时间写 verified_at 与 updated_at，并清除对象错误码。dedup_hash 由数据库生成，唯一键冲突返回 ErrStoredObjectDedupConflict，供调用方重新选择。对象写入随外层事务提交或回滚。

第 314 步 SelectUploadPublicationObject 在写回复核事务内串联复用查询和暂存对象推进。唯一键冲突时以相同用户、摘要及大小做一次加锁重查。正式 MySQL 验证复用、推进提交及外层回滚，冲突后的查询分支由测试驱动固定执行顺序。本次选定的对象 ID 供后续在同一事务创建目录项。

第 256 步 CreateStagedObjectInput 的 Provider、Bucket、ObjectKey 和 SizeBytes 分别对应 provider、bucket、object_key、file_size。三项文本检查非空、ASCII 及 32/63/255 字节列宽，完整 uint64 字节数直接保留。创建参数中的位置由服务端配置及生成流程提供，所属用户由可信事务确定，后续对象插入设置 STAGING 初始阶段。领域及正式迁移文本对照、列宽/编码/大小边界和上传声明组装回归连续三次通过。

第 257 步 NewStagedObject 显式创建 owner_user_id、provider、bucket、object_key、file_size、status 六列，字段使用仅创建写入权限。其余十一列由自增、默认值、NULL 或生成列表达，正式迁移逐列核对可省略条件。真实 MySQL 映射插入后按所属用户和存储位置取得 ID，再复用 FindUserStoredObject 检查 STAGING、八项 NULL、自动时间及完整大小。位置唯一键、所属用户外键、文本列宽和完整无符号绑定连续三次验证，独占验证库沿用自动清理复核。

## 7. 目录与唯一约束设计

### 7.1 根目录及命名

根目录使用真实 file_entries.id，普通目录项引用它。根目录生成键 root_owner_id 对 user_id 建唯一约束，保证每个用户最多一条根记录。账号初始化事务保证存在且仅存在一条根记录。

普通展示名限定为 1～120 个 UTF-16 代码单元。归一化规则按 NFC → Unicode case folding → NFC 执行，结果以 UTF-8 编码保存为 name_key，长度最多 768 字节。客户端和服务端共用命名测试样例，服务端为最终校验方。名称去除首尾空白，并校验路径分隔符、控制字符、保留设备名和末尾句点。

活动名称键采用生成列，其规则写为以下表达式。

~~~text
root_owner_id = CASE WHEN parent_id IS NULL THEN user_id ELSE NULL END
active_name_key = CASE WHEN status = 'ACTIVE' THEN name_key ELSE NULL END
dedup_hash = CASE WHEN status = 'READY' THEN verified_sha256 ELSE NULL END
~~~

生成列统一采用 STORED。唯一索引允许多个 NULL，适合保留多份同名回收记录。生成列条件与物理外键采用 RESTRICT 策略，实施时验证 DDL 组合限制。[MySQL 唯一索引](https://dev.mysql.com/doc/refman/8.4/en/create-index.html) [MySQL 生成列](https://dev.mysql.com/doc/refman/8.4/en/create-table-generated-columns.html)

### 7.2 同用户外键与目录语义

父表为复合引用提供明确唯一键 (user_id, id)，stored_objects 对应 (owner_user_id, id)。实施时显式建立子表配套索引，字段类型和排序规则保持一致。[MySQL 外键文档](https://dev.mysql.com/doc/refman/8.4/en/create-table-foreign-keys.html)

复合外键约束跨账号误关联。父项必须为 DIR、目标及全部祖先必须有效、目录不能移动到后代等规则在持有用户锁的事务中检查。第一期保持 user_id 不可修改。

第 157 步子树统计按同用户的真实 parent_id 关系包含源自身及全部保留后代，覆盖 ACTIVE、TRASHED、PURGING、PURGED，源深度为 0。采用单条递归 CTE 汇总节点数量和最大相对深度，当前事务可复用其连接和快照。统计返回实际数量，后续服务据此校验 10000 项规模上限，并结合目的地路径计算移动后最终层级。

第 158 步将统计和已校验目的地路径组合为移动限制。数量包含源自身，最多 10000 项；目标父目录深度为根到目标路径长度减一，移动后最深节点深度为目标父目录深度 + 1 + 子树最大相对深度，最多 32。内部范围或结构异常先返回数据错误，规模超限先于最终层级超限判断。

第 159 步位置写入在已认证用户事务内执行，先按当前用户定位源和目标，再按主键升序逐项加锁。版本匹配且当前父目录等于目的地时返回当前记录，实际移动条件更新 parent_id、revision、modified_at、updated_at 四项字段，名称键由既有记录参与目标父目录的活动唯一约束。写后核对基础结果，外层统一确认提交或回滚，完整祖先、子树关系与限制在同一用户事务中由上层服务检查。

第 160 步移动核心服务在一次已认证用户事务中组合上述关系、统计、限制和条件写入，全部调用使用当前事务 Store。两端路径及关系校验后检查源版本，再取得子树统计；同位置也执行规模与最终层级限制。服务核对写后基础结果，外层失败时回滚，确认提交后返回独立记录。

### 7.3 回收站与永久清理

回收一个目录时仅将被操作根项设为 TRASHED，保留其 parent_id。后代的有效可见性由全部祖先状态共同决定。收藏、最近使用、全局搜索、下载授权和对象复用查询都应用同一祖先检查。

回收站只展示自身为 TRASHED 且没有回收或清理中祖先的项目，保留原路径便于恢复。默认 30 天到期后进入永久清理队列。

永久清理先将根项设为 PURGING，使整个子树立即不可访问。后台每批最多处理 100 项，以叶子优先标记 PURGED，释放其逻辑额度并清除 object_id，删除对应偏好。事务中的条件更新保证每个文件只结算一次。状态记录构成恢复进度，重启后继续选择尚未 PURGED 的后代，最终完成根项。

目录内先前已独立回收的后代也属于永久清理范围，操作确认显示受影响数量。同步阶段需把每批清理事件一并写入变更日志。

PURGED 墓碑至少保留 90 天，上传历史等引用尚存时继续保留。清理墓碑按子项优先执行，并先清理已到保留期的任务及幂等引用。活动根目录长期保留。

## 8. 状态机及一致性

### 8.1 物理对象

~~~text
STAGING → VERIFYING → READY
STAGING / VERIFYING → ORPHANED
READY / ORPHANED → DELETING → DELETED
~~~

存储会话未完成时，清理需要 AbortMultipartUpload。完成对象的清理通过 DeleteObject。READY 对象由不可变键定位，内容替换创建新对象。

对象失去最后一个有效引用时记录 unreferenced_at，gc_after 设为该时间加 7 天。创建新引用时清空这两个字段。清理时重新核验逻辑文件、回收站、非终态任务和保留版本引用，确认连续无引用后标记 DELETING 并在事务外删除对象。

第 323 步 ClearPublishedObjectGCTimer 在同一用户事务中当前读活动文件及 READY 对象。核对文件确实引用该对象且大小一致后，按旧 unreferenced_at、gc_after 条件清空两列，并写入 UTC 微秒更新时间。两列原为空时直接返回；外层提交或回滚同时处理引用及计时。正式 MySQL 验证宽限期内、计时到期但仍 READY、重复调用和跨账号边界。

PURGING 目录中的后代在各自完成 PURGED 事务前继续保持有效内容引用。对象创建后从未发布的情况，以任务终结并进入 ORPHANED 的时刻开始计算宽限期。元数据历史引用与实际内容引用分别核对，完成任务保留的审计外键指向对象记录，内容删除后对象记录进入 DELETED。

第 324 步 MarkDeduplicatedUploadObjectOrphaned 加锁读取当前用户的 COMPLETED 任务，以 staged_object_id 和 published_object_id 的差异定位冗余副本。复用既有孤立标记的当前读，检查未 PURGED 文件与未终结任务引用。状态从 VERIFYING 条件写为 ORPHANED，以数据库 UTC 微秒时间写入无引用起点和七天清理期限。任务的审计外键与已发布对象仍可用于追溯。

### 8.2 上传任务

~~~text
CREATING → UPLOADING → COMPLETING → VERIFYING → COMPLETED
UPLOADING → VERIFYING                         小文件路径
非终态 → CANCELLING → CANCELLED
非终态 → EXPIRING → EXPIRED
不可恢复错误 → FAILED
~~~

网络瞬时错误保留原阶段，更新 next_attempt_at、attempt_count 和错误摘要。COMPLETED、CANCELLED、EXPIRED、FAILED 为终态。任务终结时释放或结算 reserved_bytes，继续通过对象状态处理存储清理。

第 242 步领域模型 UploadStatus 使用十个精确字符串常量对应 ck_uploads_status，IsTerminal 对齐 ck_uploads_terminal 的四个终态。IsValid 与 IsTerminal 只读取状态值，后续持久任务事务负责阶段推进、终态预占归零及成功结果完整性。专项通过 migrations.InitialSQL 对照正式迁移中的两项约束，核对十种合法值和四种终态，覆盖处理中取消/过期、COMPLETING、零值及非规范文本。

用户在客户端暂停传输时保存本地队列状态，服务端任务保留可续传阶段。取消请求参与服务端状态竞争，已完成任务返回完成结果。

### 8.3 锁顺序与事务

首期同账号关键写事务首先锁 users 行。其后统一按 file_entries、stored_objects、upload_tasks、user_entry_preferences、idempotency_records 的顺序加锁，同表多行按主键升序。对象网络操作在事务外执行，租约以数据库时间计算。

| 场景 | 事务内原子动作 | 事务外动作 |
|---|---|---|
| 创建账号 | 插入用户、创建根目录 | 返回初始化结果 |
| 创建上传 | 校验归属/目标/配额，预占空间，创建对象记录、任务和幂等结果 | 创建存储上传会话，条件回写会话 ID |
| 上传发布 | 核验租约及状态，选定 READY 对象，确定最终文件名，创建目录项，reserved 转 used，任务完成 | 提交后返回资源 ID |
| 秒传 | 校验同账号现存可访问引用，增加逻辑目录项与用量，记录幂等结果 | 返回结果 |
| 重命名或移动 | 校验 expected_revision、目标、祖先及名称唯一，更新元数据和 revision | 返回新元数据 |
| 回收与恢复 | 更新根项状态、名称键、时间和 revision | 返回结果 |
| 永久清理一批 | 条件标记叶子项、释放逻辑用量、清除内容引用及偏好 | 后续 GC 处理物理内容 |
| GC 领取 | 锁定用户和对象，核验无引用及宽限期，进入 DELETING | 存储删除及结果回写 |
| 内容替换 | 保留旧版本，替换当前引用，结算新内容完整预占，更新 revision | 后续到期版本清理 |

同步上线时，涉及命名空间的事务追加 change_seq 和 change_events 写入。账号锁会串行化单账号元数据写入，首期接受这项取舍，数据流传输仍可并发。

### 8.4 故障恢复矩阵

| 故障窗口 | 预期恢复 |
|---|---|
| 预占完成、存储初始化失败 | 任务重试或过期，终态释放预占 |
| 创建 Multipart 后写库失败 | 按固定对象键核对，无法关联的会话进入延迟清理 |
| Complete 响应丢失 | Head 唯一对象键并核对任务，继续校验 |
| 内容已完成、元数据提交失败 | 保留 VERIFYING，恢复后幂等发布 |
| 旧 worker 租约失效后返回 | 条件写必须匹配 lease_version，丢弃旧结果 |
| 两任务上传同哈希内容 | 唯一键冲突后复用已有对象，丢弃副本进入 ORPHANED |
| 发布与取消并发 | 事务先提交者确定结果，额度仅结算一次 |
| 永久清理中断 | 依据 PURGING/PURGED 状态继续处理剩余叶子 |
| 删除对象成功、结果回写失败 | 重试删除，已不存在视为完成 |
| 恢复与名称创建并发 | 在账号锁下选择可用后缀，唯一键作为最终保护 |

## 9. 配额核算与查询策略

### 9.1 核算规则

used_storage 等于所有未 PURGED 的 FILE 大小之和，加后续未清理 file_versions 大小。父目录回收只改变可见性，后代仍计入。reserved_storage 等于所有上传任务 reserved_bytes 之和。

上传开始预占完整声明大小。完成时等额从 reserved 转入 used，任务 reserved_bytes 归零。秒传创建新逻辑副本仍按完整大小增加 used。同名上传保存为新逻辑副本。

第 261 步 ReserveUserUploadSpace 在已认证用户事务中锁定当前配额，按 used_storage <= storage_quota、reserved_storage <= storage_quota-used_storage 检查既有事实，再比较声明与剩余配额，避免无符号加减溢出。正值以原配额条件更新 reserved_storage，零字节核对后结束。正式 MySQL 连续三次验证并发防超额、最大无符号数、回滚及单连接重复预占，并将用户预占、暂存对象和上传任务放在同一事务提交，核对用户预占等于任务预占之和。

第 321 步 SettlePublishedUploadQuota 复用用户配额当前读。校验任务仍有完整预占，且本次字节数不超过账号总预占后，计算新的 used_storage 与 reserved_storage。在同一条条件 UPDATE 写入两项新值及任务 reserved_bytes=0，绑定旧账目、当前任务和有效校验租约，并用数据库时间更新双方记录。零字节结算仅复核当前状态和期限。结算与文件、对象和任务完成共用外层事务。

第 264 步 CreateUploadService 将上述预占与暂存对象、SINGLE 任务创建串入同一已认证用户事务，写入前检查目标目录及全部祖先和新增文件深度。外层确认后返回 UPLOADING 任务，任务预占与用户预占同时增加，used_storage 和 change_seq 保持其现有含义。正式 MySQL 联测在预占、对象、任务三个真实写入阶段后注入失败与取消，分别确认整体回滚；双并发请求竞争剩余空间得到一次完整创建与一次配额不足。用户预占总额与任务预占汇总核对一致，幂等结果保存由后续服务编排复用核心入口。

内容替换保留旧版本时，新内容按完整大小预占。发布后旧文件大小从当前引用转为历史引用，仍计入 used，新内容大小新增到 used。历史版本到期后释放一次相应额度。

每日及异常恢复后执行聚合核对。核对修正也锁定用户行，在同一一致性边界内读取并更新。统计接口同时展示逻辑配额与预占，物理磁盘剩余容量另行监测。

### 9.2 页面查询

| 查询 | 过滤与排序 | 数据访问安排 |
|---|---|---|
| 当前目录 | user_id、parent_id、ACTIVE，modified_at/id 降序 | 先验证目录及祖先，再做目录索引分页 |
| 收藏 | starred_at 非空 | preferences 与 entries 联查，过滤祖先回收状态 |
| 最近使用 | last_opened_at 非空且 FILE | 按访问时间/id 降序，过滤失效引用 |
| 全局文件名搜索 | 当前用户、ACTIVE、归一化名称包含匹配 | 第一阶段使用有界扫描，LIKE 参数转义 % 和 _ |
| 类型筛选 | category | 父目录内或全局范围由 API 明确指定 |
| 按大小或名称排序 | file_size/id 或 name_key/id | 小规模集合排序，实测后增补专用索引 |
| 回收站 | TRASHED，deleted_at/id 降序 | 排除具有失效祖先的嵌套回收项 |
| 上传列表 | user_id、status，created_at/id 降序 | 用户任务索引 |
| GC 和恢复队列 | status、到期时间或租约 | 小批领取，锁行后重新确认条件 |

第 198 步的收藏候选读取使用 EXISTS 子查询，按当前用户及 entry_id 关联 user_entry_preferences，要求 starred_at 非空，并与活动状态、原文搜索、分类及修改时间/ID 翻页组合。仅访问、空偏好及缺省偏好由收藏条件排除，根目录由普通项条件排除，完整祖先可见性在同一快照中由上层检查。

第 199 步的全局可见列表服务已组合 starred 候选、完整父链可见性和有界补读，候选与祖先读取位于同一只读快照。祖先依其归属、目录类型及活动状态判断可见性，收藏成员资格应用于候选目录项。

第 208 步的最近使用可见列表服务在同一只读快照内组合最近候选、完整祖先链过滤和有界补读。原访问时间随可见文件保留，每批至多一百项、一次至多检查一千项，最后消费的访问时间/ID 用于续页。预算短页或空页继续携带位置，候选耗尽时结束。父目录及访问偏好在候选读取后被外部事务修改时，当前查询沿用原快照，后续新查询取得已提交事实，相关正式表场景连续三次通过。

第 217 步定义 NameEntryPosition，使用现有 file_entries.name_key 的原始 []byte 与目录项 ID 表达名称键、ID 双升序位置，名称键容量沿用 VARBINARY(768)。位置校验接受 1～768 字节及非零 uint64 ID，名称生成仍按既有 NFC、Unicode case folding、NFC 流程执行。分页位置保存最后扫描候选，供后续名称候选查询和预算续页使用。

第 218 步按当前用户、ACTIVE 和普通目录项条件读取名称升序候选，额外投影 name_key，排序使用 name_key ASC、id ASC，续页按名称键大于位置键或同键且 ID 更大的条件绑定。all/starred、名称搜索和分类在 ORDER BY 与 LIMIT 前组合，收藏范围复用当前用户的非空 starred_at 条件。名称键使用 VARBINARY 原始字节，候选包含隐藏路径项供后续同快照可见性检查。

第 219 步的名称升序可见列表服务在同一只读快照内组合名称候选和完整父链，范围及搜索/分类条件逐批保留，每批至多一百项、请求预算一千项。页满或预算耗尽时保存最后消费的 name_key/id，候选耗尽后结束，隐藏路径过滤后的空页可以携带内部位置。正式表快照对照覆盖读取后父目录移动、名称键变化及收藏取消，单连接也能完成候选、资料和祖先读取。

第 220 步的名称签名游标把 name_key 原始字节编码为无填充 Base64URL，保留同键 ID 的完整十进制文本，绑定用户、all/starred、name_asc 和搜索/分类摘要。名称键容量 768 字节对应 1024 个编码字符，版本 1 最长完整游标文本为 1691 字节，名称游标文本上限为 2048 字节。真实普通及预算位置在测试内独立检查签名、解码原始键后继续名称可见列表读取。

第 221 步的名称游标校验器按 HMAC、版本/绑定、规范字节编码及位置容量还原独立 name_key/id，重签名比较完整文本。正式表的普通与预算续页位置使用正式校验器，并与独立解码的数据库键/ID 对照，合法页大小变化复用原文本，错误绑定在服务续读前拒绝。

第 222 步的名称文本分页服务连接校验、可见列表与签名，按名称键/ID 严格升序交付，下一位置允许指向最后消费的隐藏候选。正式表验证 all/starred 普通及预算文本续读，两个跨目录同键文件保存 768 个 0xff 字节名称键，实际游标超过 1024 字节，使用名称用途的 2048 字节容量并允许调整合法页大小继续读取。

第 227 步将名称读取链连接正式 GET /api/v1/entries 的 all/starred、name_asc 分支，启动时复用 WithFileEntrySnapshot 及持久化主密钥派生名称用途游标。真实启动/重启验证普通、收藏、预算隐藏位置和 768 字节二进制同键的原游标续读，按 name_key/id 双升序读取，分页格式继续保存最后消费的候选位置。

第 228 步定义 SizeEntryPosition，字段 FileSize、ID 对应现有 file_entries.file_size 及 id 的 BIGINT UNSIGNED，排序约定为 file_size/id 双降序。零字节是有效大小，位置以非零 ID 校验，支持完整 uint64 范围并可保存最后扫描候选，供后续大小候选与预算续页使用。

第 229 步按用户、ACTIVE 和普通目录项条件读取大小降序候选，排序采用 file_size DESC、id DESC，续页绑定大小更小或大小相同且 ID 更小的条件。all/starred、原文搜索及分类在 ORDER BY/LIMIT 前组合，收藏使用当前用户非空 starred_at 的 EXISTS 条件。零字节与完整 BIGINT UNSIGNED 大小均进入稳定二元分页，隐藏父链候选交由后续同快照可见性服务处理。

第 230 步大小可见列表服务在同一只读快照中组合 file_size/id 候选及完整父链过滤，读取范围和筛选逐批保留。每批至多一百项，请求扫描预算一千项，页满或预算耗尽时保存最后消费候选的大小/ID。正式表验证大小与收藏事实、父目录移动的快照对照，以及预算空页/短页继续读取和零字节目录的稳定次序。

第 231 步的大小签名游标以十进制字符串保存 file_size 和 id 的完整 BIGINT UNSIGNED 值，零字节可作为续页大小。七字段载荷绑定用户、all/starred、size_desc 和原文搜索/分类摘要，使用大小用途 HMAC-SHA256，文本上限 1024 字节，版本 1 最大文本 355 字节。真实普通、收藏及预算隐藏位置在测试内独立核验签名和七字段，从文本还原大小/ID 后继续可见列表读取。

第 232 步大小游标校验器先检查大小用途 HMAC，再核对版本、当前用户、范围、排序及原文筛选绑定，通过规范十进制还原完整 file_size/id，零大小有效。重签名核对全部文本，重复/额外字段、数值表示或编码变化统一拒绝。正式表的普通、收藏和预算位置使用正式校验器，与独立解码大小/ID 对照后续读，合法页大小调整沿用原文本，错误绑定在读取前拒绝。

第 233 步大小文本分页服务连接首页、游标校验、同快照可见列表及下一页签名。可见项按 file_size/id 严格降序交付，下一位置严格越过输入位置，并允许等于最后可见项或指向其后的隐藏候选。真实表验证普通/收藏、零字节、合法页大小调整、预算空页/短页继续读取，以及完整最大无符号大小/ID、超过有符号范围大小和零目录的三页文本续读。

第 234 步大小分页响应转换复用 DirectoryEntrySummary，公开 ID、parent_id 和 revision 为完整十进制字符串，size_bytes 为 JSON 安全整数，created_at/modified_at/updated_at 转为 UTC 微秒时间。DTO 保留大小服务给出的顺序及真实父目录，空 items/breadcrumbs 使用 []，预算页携带独立 next_cursor，结束为 null，真实普通/收藏及预算文本分页逐项核对公开数据和数据库事实。

第 235 步通过 SizeEntryPageSuccess 交付正式表大小分页结果，在测试专用 GET 入口核对 HTTP 200、UTF-8 JSON、请求 ID 及禁止缓存头。普通/收藏、合法页大小调整、零字节、预算空页/短页/边缘和结束页的完整正文与 DTO 编码一致，预算游标继续读取原大小位置，单次查询内的快照及排序事实延续至响应。

第 236 步大小查询 DTO 将 URL 中的 all/starred、size_desc、搜索、分类、游标及页大小转换为类型化输入，搜索和游标保留一次解码后的原值。正式表普通/收藏、零字节和预算续页通过 DTO 进入大小分页服务，查询中的用户和父目录额外字段沿用忽略策略，数据库归属仍来自可信 Actor，真实 GET 条件再次解析并逐项对照。

第 237 步大小列表处理函数通过可信 Actor 连接查询、同快照分页及 HTTP 交付。正式会话/JWT 验证普通/收藏跨目录读取、大小/ID 双降序、零字节文件和预算隐藏位置续页，错误用户、范围、筛选和其他用途游标统一拒绝。账号中途禁用及快照结束失败在真实请求中返回对应错误，公开结果交付前再次核对当前用户及请求页大小。

第 238 步将大小读取链连接正式 GET /api/v1/entries 的 all/starred、size_desc 分支，启动入口复用 WithFileEntrySnapshot 和持久化主密钥派生的大小游标。正式启动与重启验证大小/ID 双降序、同大小及零字节、收藏、搜索/分类和扫描预算，最后消费隐藏位置可跨重启续读，页大小调整保留用户/范围/筛选绑定。

祖先状态可用深度受限的递归查询或批量读取父链确认。全局查询先扫描候选，再做祖先过滤，继续读取至页面填满或候选扫描上限。游标记录最后扫描候选的位置，达到上限时允许返回短页和 next_cursor，避免隐藏项目造成跳页。

默认分页 50 项，上限 100。排序使用稳定的二元游标，大小和名称排序时也附带 id。第一阶段按单账号十万项以内做验证，包含匹配查询接受扫描成本，扩容依据 EXPLAIN 和真实耗时决定。

## 10. MinIO 数据布局

开发环境沿用私有 Bucket cloudnest。对象键建议为 users/{user_id}/objects/{random_uuid}，使用生成的 ASCII 标识。provider 通过应用配置解析 endpoint 和凭证。

第 263 步 GenerateUploadObjectKey 已沿用上述布局，使用完整十进制用户 ID 和规范小写 UUIDv4，键长 52～71 字节，满足 object_key 的 ASCII 与 VARCHAR(255) 列约束。UUID 默认使用安全随机源，每次新暂存尝试生成独立位置，后续读取和内容处理使用该对象已保存的键。位置唯一性同时由 (provider, bucket, object_key) 约束核对，冲突沿用 ErrStoredObjectLocationConflict。正式 MySQL 联测验证生成位置原样持久化、双用户多次尝试、重复位置冲突与外层回滚，最大用户 ID 前缀完整保留。

同一用户的两个逻辑文件可引用同一 READY 对象。重命名、移动及回收仅修改元数据。对象内容校验完成后才允许通过目录项授权下载或秒传。

元数据发布前通过 Head 和必要的流式读取核对大小及 SHA256。MySQL 的状态和存储端实际状态发生偏差时，恢复任务根据唯一对象键和任务标识进行核对。ETag 原样保存。

文件真实存在于 MinIO 但尚未发布时，保持任务可恢复状态。定时扫描仅处理应用前缀和经过宽限期核验的对象，避免删除其他应用数据。

### 11.1 后续验收清单

- 两账号不能建立跨账号目录、设备、对象或偏好引用。
- 同账号并发创建根目录只能成功一次，根目录始终可定位。
- 同目录大小写和 Unicode 等价名称冲突，回收站允许同名历史条目。
- 目录移动到自身或后代被拒绝，父目录回收后通过后代 ID 的访问同样受限。
- 全局搜索、收藏和最近使用均过滤回收目录内的后代。
- 并发上传配额临界值时不会超额，完成、取消和过期重试只结算一次。
- 同哈希并发上传能够复用对象，两个逻辑文件各自保留正确配额。
- 目录分批永久清理中断后可恢复，任一仍被引用的对象不会被 GC。
- 丢失 Complete 响应及元数据提交失败后，任务可恢复到唯一发布结果。
- 租约过期的旧 worker 不能提交状态或配额变化。
- 文件收藏与预览更新不改变文件 revision，最近打开与修改时间独立。
- 恢复时父目录失效或出现同名，结果名称与目标位置明确返回。
- 迁移演练、备份恢复及数据与对象清单核对通过。

### 11.2 保留与备份约定

| 数据 | 建议保留规则 |
|---|---|
| 上传终态任务与分片核对记录 | 终态后 30 天，清理时先处理分片子表 |
| 幂等记录 | 至少 7 天，长任务通过稳定 task_id 继续查询 |
| 过期或撤销认证会话 | 终结后 30 天 |
| 撤销设备 | 保留身份墓碑及文件来源关联 |
| PURGED 目录项和 DELETED 对象记录 | 至少 90 天，存续外键引用消失后才能清理 |
| 同步变更日志 | 同步阶段至少 90 天，结合有效设备确认和重建基线策略清理 |

首期每日执行一次一致性备份，目标 RPO 为 24 小时，RTO 为 4 小时。维护窗口暂停元数据写入、对象发布和 GC，等待相关事务结束后导出 MySQL、对象清单及其大小和 SHA256，将引用内容复制到独立备份位置。完成清单核验后恢复写入。

在全新隔离环境演练恢复，核对目录、回收站、配额、文件哈希和对象位置。恢复期间处理失效上传会话及其预占，确认认证配置和存储可达性后开放访问。RPO 与 RTO 以演练记录验收。
